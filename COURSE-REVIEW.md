# Ревью курса JS Core

Сплошной разбор курса: 4 блока, 11 учебных модулей, 63 урока, 102 задачи.
Документ рабочий — правки вносятся в него же по мере исправления.

Дата разбора: 6 сентября 2026.

## Как это проверялось

1. Весь контент выгружен из боевой базы (та же Neon, что у прода) — не из
   файлов `seed/`, потому что уроки давно редактируются в админке и файлы
   отстали.
2. Все 102 задачи выгружены из `src/lib/tasks` вместе с заготовками,
   проверками и ожидаемыми значениями.
3. Все восемь тестов-в-уроке пересчитаны вручную: каждое выражение вычислено,
   отмеченные варианты сверены.
4. Спорные места проверены **исполнением**: неверные решения прогнаны через
   настоящий `buildWorkerSource` в изолированном контексте. Ниже помечено,
   какие находки подтверждены прогоном, а какие — наблюдение.
5. `npm run audit:content` прогнан на живых данных.

## 1. Оценка в целом

### Коротко

Курс сильный. Тексты уроков написаны человеческим языком, без академизма;
почти в каждом есть та самая деталь, которую обычно узнают через полгода
работы («`fetch` не считает 404 ошибкой», «`GET` попадёт в историю вместе
с паролем», «текст только через `textContent`»). Задачи не срисованы с
Codewars: у большинства есть служебные функции, которые проверяют не только
результат, но и способ — метод в прототипе, а не в экземпляре; новый объект,
а не изменённый старый.

Главная проблема — **не равномерность, а её отсутствие**. Курс сделан
слоями, и слои разного качества. Хуже всего сделан первый модуль, с которого
курс начинается; лучше всего — второй и третий блоки, до которых ученик
должен ещё дойти.

### Вход с нуля: тут и провал

Первый модуль, «Примитивные типы данных», — единственный в курсе, где
**нет текста уроков**.

| Модуль | Уроков | Из них без текста |
|---|---|---|
| Примитивные типы данных | 7 | **6** |
| все остальные 10 модулей | 56 | 0 |

Что видит ученик в первый день:

```
Урок «Типы данных»
  → видео 20 минут (ВК)
  → ссылка на learn.javascript.ru
  → ссылка на MDN
  → задача: тест на типы данных
```

Больше ничего. Ни абзаца своими словами, ни примера кода на странице, ни
краткого содержания (`summary` пуст у шести уроков из семи), ни описания
у самого модуля. Ученик, у которого не пошло видео или который просто хочет
быстро освежить память, не получает **ничего**.

Сравните с уроком «Объекты» из второго модуля: там абзац про пары
«ключ — значение», пример кода, отдельное предложение про то, зачем нужны
квадратные скобки — и только потом видео и статья. Разница в качестве входа
колоссальная, и она приходится ровно на тот момент, когда ученик решает,
продолжать ли.

Дальше та же картина по остальным опорам:

| | Тест-самопроверка | Разминка перед задачей |
|---|---|---|
| Примитивные типы данных (7 уроков) | 1 | 3 |
| Ссылочные типы (7 уроков) | 0 | 3 |
| Продвинутые функции (6 уроков) | 6 | 6 |
| Перебор массивов (3 урока) | 3 | 2 |

То есть механика «прочитал → проверил себя тестом → размялся на простом →
решил настоящую задачу» работает начиная с третьего модуля. Первые два
модуля — самые важные для новичка — идут по схеме «посмотри видео → реши».
Жалобы на сложность задач почти наверняка растут отсюда: задача не сложнее
других, просто к ней не подвели.

### Провал второй: конец курса без практики

| Модуль | Уроков | Задач | Разминок |
|---|---|---|---|
| Работа с DOM | 6 | 6 | 0 |
| Сетевое взаимодействие | 5 | **2** | 0 |
| HTTP, DNS и REST | 8 | **2** | 0 |

Одиннадцать уроков программы не имеют ни одной задачи, и девять из них — не
проектные, а обычные: `local-storage`, `ajax-basics`, `ajax-requests`,
`how-internet-works`, `dns`, `http`, `api`, `request-testing`,
`async-code/review-booking`.

Блок «Browser API и HTTP» — 19 уроков и 10 задач на всех. Для сравнения:
блок «Основные концепции» — 23 урока и 46 задач. Ученик доходит до конца
курса и последние три недели в основном читает.

Отдельно: в блоке Browser API **ноль разминок**, хотя именно там появляются
самые непривычные вещи — событийная модель, промисы в живом коде, CORS.

### Что сделано хорошо и трогать не надо

- **Разминки как приём.** «Ступенька к задаче X» с явным объяснением, что
  именно эта ступенька даёт, — редкая и очень правильная вещь. Текст вроде
  «Разберётесь здесь — `sequenceSum` устроена так же: только вместо
  умножения сложение» стоит десяти абзацев теории.
- **Служебные функции в заготовках.** Они позволяют проверять не результат,
  а способ: `ownMethod: false` в `point-constructor`, `sameInstance: false`
  в `rectangle-class`, `immutable: true` в `fluent-calc`. Это то, чего нет
  ни на одной публичной платформе с задачами.
- **Тексты про безопасность и эксплуатацию.** `rel="noreferrer noopener"`,
  `textContent` против `innerHTML`, токен не в `localStorage`, пароль не в
  `GET` — всё на своих местах и без запугивания.
- **Тест на приведение типов.** Восемь вопросов, все посчитаны верно (я
  пересчитал каждый). Это сильный, честный тест.

## 2. Что чинить в задачах и проверках

Разделено на две части: подтверждённое исполнением и наблюдения.

### 2.1. Подтверждено прогоном: проверки пропускают неверное решение

Каждый пункт ниже я написал неверным способом и прогнал через настоящий
скрипт воркера. Все указанные решения **проходят все проверки**.

#### `replace-items` — задача не проверяет то, ради чего написана

`src/lib/tasks/reference-types/pure-functions/replace-items.ts`

Урок называется «Чистые функции». Задача просит написать две функции: чистую
и мутирующую. Проверок три, и все три смотрят только на **возвращённое
значение**. Обе функции, написанные одинаково чисто, проходят 3 из 3:

```js
function replaceItemsClear(arr, item, replaceItem) { return arr.map((x) => (x === item ? replaceItem : x)); }
function replaceItemsMutate(arr, item, replaceItem) { return arr.map((x) => (x === item ? replaceItem : x)); }
```

Ученик может пройти задачу про мутацию, ни разу ничего не изменив, и не
узнать разницу — а именно за этим задача и стоит в уроке.

**Как чинить.** Две служебные функции, которые показывают не только
результат, но и судьбу исходного массива:

```js
function checkClear(arr, item, replaceItem) {
  const source = [...arr];
  const result = replaceItemsClear(source, item, replaceItem);
  return { result, sourceAfter: source, sameRef: result === source };
}

function checkMutate(arr, item, replaceItem) {
  const source = [...arr];
  const result = replaceItemsMutate(source, item, replaceItem);
  return { result, sourceAfter: source, sameRef: result === source };
}
```

Для чистой ждём `sourceAfter` равным входу и `sameRef: false`, для
мутирующей — `sourceAfter` равным результату и `sameRef: true`. Тогда обе
подмены ловятся сразу, и красная строка сама объясняет, что не так.

#### `move-to-start` — «новый массив» не проверяется

`src/lib/tasks/reference-types/arrays/move-to-start.ts`

В условии: «верните новый массив. Исходный массив изменять нельзя». Решение,
которое режет исходный массив через `splice` и возвращает его же, проходит
3 из 3:

```js
function moveToStart(arr, n) {
  if (n >= arr.length) return arr;
  const tail = arr.splice(arr.length - n, n);
  arr.unshift(...tail);
  return arr;
}
```

**Как чинить.** Служебная функция, возвращающая `{ result, sourceAfter, sameRef }`.

#### `numbers-by-parity` — классическая ошибка с отрицательными не ловится

`src/lib/tasks/reference-types/arrays/numbers-by-parity.ts`

В JavaScript остаток сохраняет знак делимого: `-3 % 2 === -1`, а не `1`.
Поэтому `n % 2 === 1` не считает нечётными отрицательные числа. Такое решение
проходит 3 из 3:

```js
function getNumbersByParity(data, parity) {
  return data.filter((n) => (parity === 'even' ? n % 2 === 0 : n % 2 === 1));
}
```

Ирония в том, что в задаче **есть** проверка с отрицательными — но только
для `'even'`, где ошибка не проявляется.

**Как чинить.** Добавить проверку:
`getNumbersByParity([-3, -2, -1, 0], 'odd')` → `[-3, -1]`.
Заодно в текст урока про числа стоит вынести правило знака остатка — это
одна из самых частых ошибок на собеседованиях.

#### `letters-count` — условие допускает два несовместимых прочтения

`src/lib/tasks/reference-types/objects/letters-count.ts`

Задача называется «счётчик букв», но что делать с пробелами, цифрами и
знаками препинания — не сказано, а во всех трёх проверках их просто нет.
Оба взаимоисключающих решения проходят 3 из 3: и то, что считает все символы
подряд, и то, что отбрасывает всё, кроме букв.

**Как чинить.** Выбрать прочтение, записать его в условие и добавить
проверку. Рекомендую «считаются все символы» (так задача остаётся простой и
согласуется со «ступенькой» `increment-counter`, где ключом может быть
пробел), а название поправить на «Счётчик символов» или добавить в условие:
«пробелы и знаки тоже считаются».

#### `compare-with-precision` — граница не описана и не проверена

`src/lib/tasks/primitive-types/numbers/compare-with-precision.ts`

Условие — две строки и один пример. Не сказано, включается ли сама
погрешность (`<` или `<=`) и что делать с отрицательной. Проверок на границу
нет, поэтому оба варианта проходят 4 из 4.

**Как чинить.** Дописать в условие: «числа считаются равными, если модуль
разницы **не больше** погрешности», и добавить проверку ровно на границе:
`compareWithPrecision(1, 1.1, 0.1)` → `true`.

### 2.2. Подтверждено прогоном: проверки бракуют верное решение

#### `once` — требуется поведение, о котором не сказано

`src/lib/tasks/advanced-functions/closures/once.ts`

В условии: «повторные вызовы не дают эффекта». Что они **возвращают** — не
сказано. Проверки требуют `undefined`. Каноническая реализация (та, что в
lodash: повторные вызовы возвращают закэшированный результат первого)
получает 0 из 2:

```
✗ Исходная функция вызывается только один раз
   получено {"calls":[2],"results":[4,4,4]}, ожидалось results: [4, undefined, undefined]
```

Ученик видит, что `calls` совпал — то есть главное он сделал правильно, — и
не понимает, чего от него хотят.

**Как чинить.** Одна строка в условие: «повторные вызовы возвращают
`undefined` и исходную функцию не вызывают». Или, что лучше по смыслу,
поменять проверки на кэширующее поведение — оно полезнее в жизни.

#### `arrow-function-factory` — проверка стиля выдаёт себя за проверку поведения

`src/lib/tasks/array-iteration/arrow-functions/arrow-function-factory.ts`

Служебная функция содержит `usesArrowSyntax: multiply.toString().includes('=>')`.
Полностью верное по поведению решение получает 0 из 2:

```
✗ Создаёт стрелочную функцию с сохранённым множителем
   получено {"values":[3,6,15],"returnsFunction":true,"usesArrowSyntax":false}
```

Значения посчитаны верно, а красное — из-за синтаксиса. Понять это по
сообщению нельзя.

**Как чинить.** Либо убрать поле (тема урока — замыкание и фабрика, а не
синтаксис), либо написать в условии прямым текстом: «возвращаемая функция
тоже должна быть стрелочной — это проверяется» — и назвать проверку
«Возвращается именно стрелочная функция», чтобы красная строка сама себя
объясняла.

### 2.3. Наблюдения без прогона

#### `create-usernames` — год берётся из окружения

`src/lib/tasks/array-iteration/array-methods/create-usernames.ts`

Ожидаемое значение считается на сервере при загрузке модуля:

```ts
const year = new Date().getFullYear();
```

Ученик считает год в браузере. На машине владельца это Москва, на Vercel —
UTC. С 00:00 до 03:00 по Москве 1 января это **разные годы**, и задача
станет нерешаемой на три часа. Ровно та ловушка, что записана в
`AGENTS.md` в разделе «Время нельзя брать из окружения».

**Как чинить.** Не брать текущий год ни на сервере, ни у ученика: передать
год аргументом (`createUsernames(users, currentYear)`) или заменить `age` на
`birthYear` в исходных данных. Второе даже честнее — «возраст» в базе
данных сам по себе плохая идея по той же причине.

#### `dom-delegate-clicks` — проверка не проверяет то, что написано в её названии

`src/lib/tasks/browser-api/dom/dom-delegate-clicks.ts`

Проверка «Обработчик один, а не по одному на кнопку» клонирует список,
подменяет узел и заново вызывает `setupList()`. После `cloneNode` слушатели
снимаются у **любой** реализации, а повторный `setupList()` восстанавливает
и делегирование, и обработчики на каждой кнопке. Реализацию «на каждую
кнопку» ловит только следующая, четвёртая проверка.

**Как чинить.** Переименовать в «Список можно настроить заново после
пересборки» — это она действительно проверяет и это полезно. А смысл
делегирования уже закрыт четвёртой проверкой.

#### Три задачи, где часть проверок проходит пустой заготовкой

Из `npm run audit:content`:

```
optional-chaining-path — пустая заготовка проходит 3 из 7
link-prototype         — пустая заготовка проходит 2 из 6
promises-in-series     — пустая заготовка проходит 2 из 5
```

Это не ошибка: проверки ждут `undefined` или отсутствия свойства, и пустая
функция честно даёт `undefined`. Но ученик нажимает «Отправить», ничего не
написав, и видит три зелёные строки — сигнал ложный.

**Как чинить.** Достаточно порядка: поставить содержательные проверки
первыми, чтобы верхние строки в списке были красными. В
`optional-chaining-path` первой сейчас идёт полная цепочка — там уже
нормально; проблема в том, что зелёные разбросаны по списку. Второй
вариант — в тех проверках, где ждём `undefined`, возвращать из служебной
функции объект `{ value, hasProperty }`, чтобы пустая заготовка давала не
тот результат.

#### Задачи с двумя проверками

Семнадцать задач проверяются двумя случаями. Список, по убыванию риска:

| Задача | Чего не хватает |
|---|---|
| `most-senior` | пустой массив; все с одинаковым возрастом |
| `merge-objects` | один аргумент; объект без пересечений |
| `languages-statistic` | отзывы только не за 2019; год как строка |

проверяется вовсе.

### 2.4. Формулировки

- **`stop-gninnipS-My-sdroW`** — опечатка в условии: «каждое слово, которое
  содержит 5 или больше символов, **написана** наоборот» → «написано».
  Плюс три проверки, среди которых нет слова ровно из пяти букв — то есть
  граница «5 или больше» не проверена вообще. Добавить: `solution('Hello world')`
  → `'olleH dlrow'`.
- **`single-fizzbuzz`** — правила перечислены в порядке «3, 5, оба», что
  подталкивает написать проверки ровно в этом порядке и получить `'Fizz'`
  для 15. Ловушка задумана (в уроке написано «Проверьте порядок условий»),
  но в самой задаче об этом ни слова — а именно её ученик читает. Стоит
  добавить строку: «подумайте, какое условие должно идти первым».
- **`default-to`** — единственное условие в курсе, написанное «на вы» с
  канцеляритом («значение по-умолчанию», через дефис — так не пишется) и без
  разбора, зачем это нужно. Рядом лежит `safe-number` с отличным текстом.
  Стоит переписать в общем стиле.
- **`compare-with-precision`** — то же: две строки без объяснения, зачем
  вообще сравнивать с погрешностью, хотя ступенька `round-to` этот вопрос
  прекрасно ставит. Достаточно перенести туда одну фразу из `round-to`.
- **`final-grade`** — правила заданы списком без единого слова о том, что
  условия проверяются сверху вниз и что первое сработавшее выигрывает. Для
  ученика, который только прошёл `if`, это неочевидно.

### 2.5. Тесты-в-уроке

Все восемь тестов пересчитаны, **ошибок в ответах нет**. Два замечания:

1. **Тест «Преобразование типов»: 7 вопросов из 8 без пояснения.** Это самый
   сложный тест курса, стоит во втором модуле, и ученик, ответивший неверно,
   не получает ничего, кроме «неверно». Единственное пояснение — про
   `typeof null` — написано отлично и показывает, каким должен быть уровень
   остальных. Это самая дешёвая и самая заметная правка во всём курсе:
   восемь абзацев текста, и худший по обратной связи тест становится лучшим.

   Готовые пояснения к остальным семи — в разделе 6, под уроком
   «Преобразование типов».

2. **Разнобой в записи.** В одном вопросе `Boolean(<значение>) === true`,
   в соседнем `Boolean(x) == false` — нестрогое сравнение там, где по смыслу
   строгое. Мелочь, но ученик в этот момент как раз учится их различать.

### Блок 1 · Основные концепции

#### Типы данных (`osnovy-javascript-tipy-dannyh`)

**Как движок вообще хранит значение.** В памяти лежит не «число» и не
«строка», а машинное слово, часть битов которого — метка типа. В V8 целые
числа примерно до двух миллиардов (их называют Smi, small integer) хранятся
прямо внутри указателя: последний бит равен нулю — значит, это не адрес
объекта, а само число. Всё остальное — дробные числа, строки, объекты —
лежит в куче, а в переменной хранится ссылка. Отсюда две вещи, которые
кажутся странными: целочисленная арифметика заметно быстрее дробной, и
`typeof null === 'object'` — потому что в самой первой реализации `null`
был нулевым указателем, а метка «000» означала объект. Ошибку не стали
исправлять: предложение вернуть `'null'` отклонили, чтобы не сломать уже
написанный код.

Источник: v8.dev/blog/pointer-compression, learn.javascript.ru/types

#### Переменные и константы (`peremennye-i-konstanty`)

Здесь уже есть видео со звёздочкой. Дополнить его стоит одним абзацем про
**временную мёртвую зону** (temporal dead zone). Часто говорят, что `let` и
`const` «не поднимаются» — это неправда. Поднимаются все три: движок при
входе в область видимости заранее заводит все объявления. Разница в том, что
`var` сразу получает значение `undefined`, а `let` и `const` остаются
непроинициализированными, и обращение к ним до строки объявления даёт
`ReferenceError`. Проверить это можно так: если бы `let` не поднималась,
внутренняя `x` нашлась бы снаружи, а она даёт ошибку.

```js
let x = 1;
{
  console.log(x); // ReferenceError, а не 1
  let x = 2;
}
```

Ещё одно различие, которое видно только в браузере: `var` на верхнем уровне
создаёт свойство глобального объекта (`window.foo`), а `let` и `const` — нет.

Источник: learn.javascript.ru/closure, developer.mozilla.org/ru/docs/Web/JavaScript/Reference/Statements/let

#### Ошибки (`oshibki`)

**Откуда берётся стек.** Свойство `stack` не описано в основном стандарте
языка — это расширение движков, которое прижилось настолько, что его
пришлось стандартизировать отдельно. Важнее другое: стек записывается в
момент **создания** объекта ошибки, а не в момент `throw`. Поэтому

```js
const error = new Error('поздно');   // стек снят здесь
setTimeout(() => { throw error; }, 1000);  // а брошена через секунду
```

покажет строку, где ошибка была создана, а не где вылетела. Это же
объясняет, почему заранее заготовленные объекты ошибок — плохая идея.

В продакшене код собран и сжат, поэтому стек указывает на `main.js:1:48213`.
Возвращают человеческие номера строк **карты кода** (source maps) — отдельный
файл, который сопоставляет собранный код исходному; браузер подхватывает его
автоматически, если файл доступен.

Источник: developer.mozilla.org/ru/docs/Web/JavaScript/Reference/Global_Objects/Error/stack

#### Преобразование типов (`preobrazovanie-tipov`)

**Правило, из которого следуют все ответы теста.** Когда объект попадает
туда, где нужен примитив, движок вызывает внутреннюю операцию `ToPrimitive`
с подсказкой: `"number"`, `"string"` или `"default"`. Она по очереди
пробует `valueOf()` и `toString()` (для подсказки `"string"` — наоборот) и
берёт первый результат, оказавшийся примитивом. Поэтому:

```js
[] + []        // '' — у массива toString даёт пустую строку
[] + {}        // '[object Object]'
[1,2] + [3]    // '1,23' — а не массив
```

Плюс можно перехватить это поведение самому:

```js
const money = {
  amount: 100,
  [Symbol.toPrimitive](hint) {
    return hint === 'string' ? '100 ₽' : this.amount;
  },
};
money + 1;        // 101
`${money}`;       // '100 ₽'
```

**Пояснения к семи вопросам теста, которых сейчас нет.** Готовый текст:

- *«Укажите все значения NaN»* — `"4px" - 2`: минус всегда числовой, строка
  «4px» в число не приводится → `NaN`. `undefined + 1`: `Number(undefined)`
  это `NaN`. А вот `null + 1` даёт `1`, потому что `Number(null) === 0`, и
  `true + false` даёт `1` — логические значения превращаются в 1 и 0.
  Запомнить проще так: `null` ведёт себя как ноль, `undefined` — как «нет
  значения», то есть `NaN`.

- *«Укажите все случаи для которых typeof === number»* — плюс двулик: если
  хоть один операнд строка, он склеивает; все остальные арифметические
  операторы всегда приводят к числу. `"" + 3 + 8` → `"38"` (строка),
  `" -13 " + 2` → `" -13 2"` (строка). А `"10" - 5` и `"" - 3 + 8` — числа,
  потому что начались с минуса. Пустая строка при этом приводится к нулю.

- *«Все случаи для которых typeof === object»* — пояснение уже написано и
  оно отличное, менять нечего.

- *«Boolean(значение) === true»* — ложных значений ровно восемь и их проще
  выучить списком: `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`,
  `NaN`. Всё остальное истинно **без исключений**, включая пустой объект,
  пустой массив и строку из одного пробела. Отсюда классическая ловушка:
  `if (arr)` истинно для пустого массива, проверять нужно `arr.length`.

- *«Boolean(x) == false»* — здесь важно, что строка `"false"` и строка
  `"0"` — непустые строки, а значит истинны. Ложна только пустая строка.
  «Ноль в кавычках» ложным не становится.

- *«6 + "3" + false + 8»* — считается слева направо. `6 + "3"` → `"63"`
  (появилась строка — дальше только склейка), `"63" + false` → `"63false"`,
  `+ 8` → `"63false8"`. Один раз превратившись в строку, выражение уже не
  вернётся к числам.

- *«15 + 1 + null - "5"»* — `15 + 1` → `16`, `16 + null` → `16` (null это
  ноль), `16 - "5"` → `11` (минус приводит строку к числу). Строк в
  результате нет, потому что плюс встретился только с числами.

- *«8 - "9 +" - null + "11"»* — `"9 +"` в число не приводится, поэтому
  `8 - NaN` → `NaN`. Дальше `NaN - null` → `NaN`, а `NaN + "11"` → `"NaN11"`:
  плюс со строкой снова склеивает, и `NaN` превращается в текст «NaN».

Источник: learn.javascript.ru/object-toprimitive, tc39.es/ecma262 (раздел ToPrimitive)

#### Числа (`chisla`)

**Почему `0.1 + 0.2 !== 0.3`.** Все числа в JavaScript — двойной точности
по стандарту IEEE 754: 64 бита, из них 1 на знак, 11 на порядок и 52 на
мантиссу. Число хранится как двоичная дробь, а `0.1` в двоичной системе —
бесконечная периодическая дробь, ровно как `1/3` в десятичной. Её обрезают,
и ошибка вылезает при сложении. Это не баг JavaScript: то же самое в Java,
C и Python.

Отсюда следуют три практических правила:

- Целые числа точны только до `Number.MAX_SAFE_INTEGER` — это `2^53 − 1`,
  примерно 9 квадриллионов. Дальше `9007199254740992 + 1 === 9007199254740992`.
  Именно поэтому идентификаторы из чужих API приходят строками.
- Деньги в дробных числах не хранят. Хранят в копейках, целыми.
- Для сравнения есть `Number.EPSILON` — наименьшая разница между 1 и
  следующим представимым числом. Ваша задача `compareWithPrecision` — ручной
  вариант того же приёма.

И ещё: `-0` существует и отличается от `0`. `Object.is(-0, 0)` даёт `false`,
а `-0 === 0` — `true`. Заметить это можно по `1 / -0 === -Infinity`.

Источник: learn.javascript.ru/number, MDN — Number.MAX_SAFE_INTEGER

#### Строки (`stroki`)

**Строка — не массив символов.** Внутри это последовательность 16-битных
кодовых единиц UTF-16. Символы, не влезающие в 16 бит (эмодзи, редкие
иероглифы, старые письменности), кодируются **суррогатной парой** — двумя
единицами. Поэтому:

```js
'😀'.length            // 2, а не 1
'😀'[0]                // половина эмодзи, мусор
[...'😀'].length       // 1 — спред идёт по кодовым точкам
Array.from('😀').length // тоже 1
```

Правило: если строка может содержать не только латиницу и кириллицу,
переворачивать её через `split('').reverse().join('')` нельзя — суррогатные
пары развалятся. Нужен `[...str]`.

Вторая тонкость — **нормализация**. Букву «й» можно записать одним символом
или двумя (и + краткая). Выглядят одинаково, `===` даёт `false`. Приводит
их к общему виду `str.normalize('NFC')` — это то, что делают поисковые
строки и формы регистрации.

Источник: learn.javascript.ru/string, MDN — String.prototype.normalize

#### Шаблонные строки (`shablonnye-stroki`)

**Теговые шаблоны.** Перед обратными кавычками можно поставить имя
функции — и вместо готовой строки она получит части шаблона и подставленные
значения по отдельности:

```js
function highlight(strings, ...values) {
  return strings.reduce((acc, part, i) =>
    acc + part + (values[i] !== undefined ? `<b>${values[i]}</b>` : ''), '');
}

const name = 'Аня';
highlight`Привет, ${name}!`;  // 'Привет, <b>Аня</b>!'
```

Смысл в том, что функция видит подставляемые значения **до** склейки — и
может их проверить или экранировать. На этом построены `styled-components`
(CSS в шаблоне), `graphql-tag` (запрос в шаблоне) и безопасные SQL-обёртки,
которые сами подставляют параметры вместо конкатенации.

Рядом живёт `String.raw` — тег, отключающий обработку `\n` и прочих
escape-последовательностей: `String.raw\`C:\new\` вернёт путь как есть.

Источник: learn.javascript.ru/template-strings, MDN — Шаблонные строки

#### Объекты (`objects`)

**Скрытые классы.** Движок не хранит объект как словарь «строка → значение» —
это было бы медленно. Вместо этого у каждого объекта есть **форма** (в V8 её
называют hidden class или map): описание того, какие свойства есть и в каком
порядке. Объекты с одинаковой формой делят одно описание, а значения лежат
плотным массивом. Поэтому

```js
const a = { x: 1, y: 2 };
const b = { x: 3, y: 4 };   // та же форма — быстро
const c = { y: 4, x: 3 };   // другая форма, порядок важен!
```

Каждое добавление свойства создаёт новую форму. Отсюда практическое правило:
инициализируйте все поля объекта сразу в одном месте и в одном порядке, а не
дописывайте по ходу.

И отдельно — **порядок ключей**. Он не «случайный» и не «порядок вставки»:
по стандарту сначала идут целочисленные ключи по возрастанию, потом
строковые в порядке добавления, потом символы. Поэтому у объекта
`{ b: 1, 2: 2, a: 3, 1: 4 }` ключи перечислятся как `1, 2, b, a`.

Источник: v8.dev/blog/fast-properties, learn.javascript.ru/object

#### Условные операторы (`conditions`)

**`&&` и `||` возвращают не `true`/`false`, а операнд.** Точнее: `a || b`
вычисляет `a`, и если оно истинно — возвращает **его**, иначе возвращает
`b`. `a && b` — наоборот. Именно поэтому работает `const name = input || 'без имени'`
и почему в React пишут `{isLoading && <Spinner />}`.

Ловушка ровно там же: `||` реагирует на любое ложное значение, включая `0`
и `""`. Если ноль — допустимое значение, `count || 10` молча превратит его
в десять. Для этого есть `??`: он срабатывает только на `null` и
`undefined`.

```js
0 || 10    // 10 — почти всегда не то, что нужно
0 ?? 10    // 0
```

Мелочь из стандарта: смешивать `??` с `||` и `&&` без скобок нельзя — это
синтаксическая ошибка, а не приоритет. Так решили специально, чтобы никто не
угадывал порядок.

Источник: learn.javascript.ru/logical-operators, learn.javascript.ru/nullish-coalescing-operator

#### Тернарный оператор и switch (`ternary-and-switch`)

**`switch` сравнивает строго.** Это `===`, без приведения типов, поэтому

```js
const value = '1';
switch (value) {
  case 1: /* сюда не попадём никогда */ break;
}
```

Вторая особенность: `case` — не таблица переходов, как в C, а
последовательная проверка сверху вниз. Двадцать веток `switch` не быстрее
двадцати `else if`; выбор между ними — вопрос читаемости, а не скорости.

Проваливание (fall-through) — не забытый `break`, а иногда осознанный приём:

```js
switch (day) {
  case 'сб':
  case 'вс':
    return 'выходной';
}
```

Именно поэтому линтеры ругаются на `case` без `break` только тогда, когда в
ветке есть код.

Источник: learn.javascript.ru/switch

#### Циклы и итерации (`loops`)

**`for...of` работает через протокол итератора.** Он не знает про массивы —
он ищет у объекта метод `Symbol.iterator` и дальше вызывает `next()`, пока
не придёт `{ done: true }`. Поэтому одна и та же конструкция обходит массив,
строку, `Map`, `Set` и `NodeList` — и не обходит обычный объект, у которого
такого метода нет.

Свой итератор пишется в четыре строки:

```js
const range = {
  from: 1, to: 3,
  *[Symbol.iterator]() {
    for (let i = this.from; i <= this.to; i += 1) yield i;
  },
};
[...range];  // [1, 2, 3]
```

И различие, которое стоит запомнить навсегда: `for...of` идёт по
**значениям** и только по итерируемым объектам, `for...in` — по **ключам**,
включая унаследованные. Для массива `for...in` даст строки `'0'`, `'1'`,
`'2'`, а не числа, и в неудачном случае прихватит чужие свойства из
прототипа.

Источник: learn.javascript.ru/iterable, learn.javascript.ru/object-keys-values-entries

#### Функции (`functions`)

**Поднятие (hoisting) разное у объявления и выражения.** Объявление функции
поднимается целиком — её можно вызвать выше по коду. Выражение поднимается
как переменная, то есть до строки присваивания там `undefined` (или мёртвая
зона для `const`).

```js
say();                 // работает
function say() {}

shout();               // TypeError: shout is not a function
var shout = function () {};
```

И ещё: функция — это объект. У неё есть свойства `name` (движок выводит имя
даже у безымянного выражения, присвоенного переменной) и `length` —
количество **обязательных** параметров, то есть до первого со значением по
умолчанию и без учёта rest:

```js
((a, b = 1, ...rest) => {}).length;  // 1
```

На `length` построены каррирование в библиотеках и часть систем внедрения
зависимостей.

Источник: learn.javascript.ru/function-basics, learn.javascript.ru/function-expressions

#### Чистые функции (`pure-functions`)

**Почему за чистоту так держатся.** Не из идеологии, а из трёх практических
следствий. Результат чистой функции можно **закэшировать** — на этом стоит
`useMemo` и `React.memo`. Её можно **безопасно вызвать заново** — на этом
стоит стратегия перерисовки в React и повтор запросов при обрыве связи. И её
можно **проверить одним сравнением** — тесту не нужно готовить окружение.

Ограничение, о котором стоит знать сразу: `Object.freeze` защищает только
верхний уровень. Вложенный объект заморожен не будет.

```js
const config = Object.freeze({ ui: { theme: 'dark' } });
config.ui = {};          // молча ничего (в строгом режиме — TypeError)
config.ui.theme = 'light';  // а это сработает
```

Настоящую защиту дают структуры, которые нельзя изменить в принципе, —
отсюда популярность библиотек неизменяемых данных.

Источник: learn.javascript.ru/object-copy, MDN — Object.freeze

#### Массивы и базовые методы (`arrays`)

**Массив — это объект, но движок старается притвориться, что нет.** В V8 у
массива есть внутренний «вид элементов» (elements kind), и их несколько:
только маленькие целые, только дробные, произвольные значения — и для
каждого ещё вариант «с дырками». Пока массив плотный и однородный, элементы
лежат подряд в памяти и доступ к ним почти как в C. Как только появляется
дырка, вид меняется на «дырявый», и **обратно он уже не вернётся** — даже
если дырку заполнить.

Дырку делают три вещи:

```js
const arr = [1, 2, 3];
delete arr[1];      // дырка
arr.length = 10;    // семь дырок
arr[100] = 1;       // девяносто шесть дырок
```

Отсюда правило: удалять элемент нужно через `splice` или `filter`, а не
`delete`. И `length` — не количество элементов, а «максимальный индекс плюс
один»: у `[]` с `arr[99] = 1` длина 100 при одном значении.

Источник: v8.dev/blog/elements-kinds, learn.javascript.ru/array

#### Рекурсия: основы (`recursion-basics`)

**Что физически происходит при вызове.** Каждый вызов кладёт на стек кадр:
аргументы, локальные переменные, адрес возврата. Стек не бесконечен —
в браузерах около десяти тысяч кадров, точное число зависит от того,
сколько переменных в функции. Переполнение даёт `RangeError: Maximum call
stack size exceeded`.

Проверить свой лимит можно так:

```js
let depth = 0;
function dive() { depth += 1; dive(); }
try { dive(); } catch { console.log(depth); }
```

В стандарте ES2015 есть **оптимизация хвостового вызова**: если рекурсивный
вызов — последнее действие функции, кадр можно переиспользовать, и глубина
перестаёт быть ограничением. Но реализовали её только в JavaScriptCore
(Safari); в V8 и SpiderMonkey её нет и не планируется. Поэтому в JavaScript
глубокую рекурсию переписывают в цикл со своим стеком-массивом — приём,
который пригодится в следующем уроке.

Источник: learn.javascript.ru/recursion, MDN — RangeError

#### Рекурсия во вложенных структурах (`recursion-practice`)

**Циклические ссылки.** Обход дерева ломается, если структура ссылается сама
на себя:

```js
const node = { name: 'a' };
node.self = node;
```

Наивная рекурсия зациклится. Защита — множество уже посещённых узлов, причём
именно `WeakSet`, чтобы не удерживать объекты в памяти:

```js
function walk(value, seen = new WeakSet()) {
  if (typeof value !== 'object' || value === null) return;
  if (seen.has(value)) return;
  seen.add(value);
  for (const child of Object.values(value)) walk(child, seen);
}
```

Ровно этим отличаются два встроенных инструмента: `JSON.stringify` на цикле
бросает `TypeError: Converting circular structure to JSON`, а
`structuredClone` циклы понимает и воспроизводит — потому что ведёт такой же
список посещённых.

Источник: MDN — structuredClone, learn.javascript.ru/weakmap-weakset

#### Функции высшего порядка и callback (`higher-order-functions`)

**Чего стоит функция как значение.** Каждый раз, когда выполняется
`(x) => x * 2` внутри цикла, создаётся новый объект функции со ссылкой на
окружение. В горячем коде это заметно — но не потому, что «объект дорогой»,
а потому что мешает встраиванию (inlining).

Движок ускоряет вызов колбэка, подставляя его тело прямо в место вызова.
Сделать это он может, только если в этой точке колбэк **всегда один и тот
же** — такое состояние называют мономорфным. Если в один `map` в разное
время прилетают разные функции, точка становится полиморфной, а потом
мегаморфной, и встраивание отключается. Отсюда наблюдение, которое иногда
удивляет: `array.map(double)` в цикле по разным типам данных может быть
медленнее, чем обычный `for`, — не из-за `map`, а из-за разнообразия
колбэков.

Это не повод отказываться от `map` — это объяснение, откуда берутся
измерения производительности, которые «противоречат здравому смыслу».

Источник: v8.dev/blog/turbofan-jit, learn.javascript.ru/function-object

#### Замыкания (`closures`)

**Что именно удерживает замыкание.** По стандарту функция хранит ссылку на
лексическое окружение — объект с переменными той области, где она создана.
Логически она видит все переменные, но движок при компиляции определяет,
какие реально используются, и остальные не удерживает.

Практическое следствие — утечки. Классический случай:

```js
function makeHandler() {
  const hugeData = new Array(1e6).fill('...');
  const id = hugeData.length;
  return () => id;   // используется только id
}
```

В теории `hugeData` можно освободить. На практике движки не всегда это
делают: если в той же области есть `eval` или другая функция, которой
`hugeData` нужна, окружение удерживается целиком. Отсюда правило: если
замыкание живёт долго (обработчик события, таймер), не создавайте рядом с
ним больших объектов, а если создали — обнуляйте ссылку явно.

Источник: learn.javascript.ru/closure, MDN — Замыкания

#### Фабрики функций (`closures-practice`)

**Каррирование.** Фабрика предикатов — частный случай общего приёма:
функцию от нескольких аргументов превращают в цепочку функций от одного.

```js
const add = (a) => (b) => a + b;
const add5 = add(5);
add5(3);   // 8
```

Зачем: получается набор готовых, настроенных инструментов, которые можно
передавать дальше без обёрток. `filter(greaterThan(4))` читается лучше, чем
`filter((x) => x > 4)`, когда предикат используется в пяти местах.

Встроенный механизм с тем же смыслом — `bind`: он фиксирует контекст и
сколько угодно первых аргументов, возвращая новую функцию. `fn.bind(null, 5)` —
это и есть частичное применение.

Источник: learn.javascript.ru/currying-partials

#### Контекст вызова и this (`this-context`)

**`this` определяется в момент вызова, и решает это форма выражения.** Когда
движок вычисляет `obj.method`, он получает не просто функцию, а внутреннюю
структуру Reference: «функция плюс объект, от которого её взяли». Скобки
вызова достают из неё и то, и другое. Стоит разорвать эту связь — и контекст
теряется:

```js
const fn = obj.method;
fn();            // this потерян

(0, obj.method)();  // тоже потерян: запятая возвращает значение, а не Reference
```

Второй пример — не курьёз: минификаторы иногда так пишут, и код внезапно
ломается.

Куда попадает `this`, если контекста нет: в обычном режиме — в глобальный
объект, в строгом (а тело класса и модули всегда строгие) — в `undefined`.
Поэтому «потерянный контекст» в классе даёт понятную ошибку
«Cannot read properties of undefined», а в обычном скрипте молча пишет
в `window`.

Источник: learn.javascript.ru/object-methods, learn.javascript.ru/bind

#### Стрелочные функции (`arrow-functions`)

**Стрелка — не «короткая функция», а другой объект.** По стандарту у неё
отсутствуют внутренние слоты, которые есть у обычной: нет `[[Construct]]`
(поэтому `new` с ней — TypeError), нет собственных `this`, `arguments`,
`super` и `new.target`, и нет свойства `prototype`.

Все эти «нет» — одно решение: стрелка не создаёт своего окружения для
контекста, а берёт его из места, где написана, и берёт **навсегда** —
изменить нельзя даже через `call` или `bind`:

```js
const arrow = () => this;
arrow.call({ a: 1 });   // контекст из окружения, а не { a: 1 }
```

Отсюда простое правило выбора: метод объекта или класса, которому нужен
динамический `this`, — обычная запись; всё, что передаётся в другую функцию
и должно помнить окружение, — стрелка.

Источник: learn.javascript.ru/arrow-functions

#### Перебирающие методы массивов (`array-iteration-methods`)

**Цена цепочки и что с ней делают.** `data.filter(...).map(...).reduce(...)`
проходит массив трижды и создаёт два промежуточных массива. Для сотни
элементов это не имеет значения; для сотни тысяч — имеет.

Классическое решение — `reduce` за один проход. Новое — **вспомогательные
методы итераторов** (iterator helpers), которые появились в стандарте
недавно:

```js
const result = data.values()
  .filter((x) => x.active)
  .map((x) => x.name)
  .take(10)
  .toArray();
```

Здесь ничего не вычисляется, пока не понадобится результат, промежуточных
массивов нет, и `take(10)` действительно останавливает работу на десятом
элементе. Поддержка ещё не везде — это тот случай, когда перед применением
надо посмотреть таблицу совместимости на MDN (об этом — блок про чтение
документации).

И одна деталь стандарта: `reduce` без начального значения на пустом массиве
бросает `TypeError`. Начальное значение — не украшение.

Источник: MDN — Iterator helpers, learn.javascript.ru/array-methods

### Блок 2 · Прототипы и классы

#### Методы объектов (`object-methods`)

**Три уровня «что считать ключами объекта».** `Object.keys` возвращает
только собственные **перечисляемые строковые** ключи. Не собственные,
не перечисляемые и символы он не покажет:

```js
Object.keys(obj)                  // собственные перечисляемые строковые
Object.getOwnPropertyNames(obj)   // + неперечисляемые
Reflect.ownKeys(obj)              // + символы
```

Неперечисляемыми свойства становятся не только вручную: все методы, которые
вы пишете в классе, неперечисляемы по стандарту. Поэтому `Object.keys` у
экземпляра класса вернёт только поля данных — и это правильно, но объясняет,
почему `for...in` по объекту с методами ведёт себя иначе, чем ожидается.

Источник: learn.javascript.ru/object-keys-values-entries, MDN — Reflect.ownKeys

#### Spread и rest (`spread-rest`)

**Что именно копирует `{ ...obj }`.** Спред у объекта — это внутренняя
операция CopyDataProperties: она берёт собственные перечисляемые свойства и
**читает** их. Три следствия, которые ловят на собеседованиях:

- Геттер вызовется, и в копию попадёт его результат, а не сам геттер.
- Дескрипторы теряются: свойство только для чтения станет обычным.
- Свойства из прототипа не копируются вообще.

Если нужна честная копия со всеми дескрипторами, есть точный инструмент:

```js
const copy = Object.create(
  Object.getPrototypeOf(source),
  Object.getOwnPropertyDescriptors(source),
);
```

И то, о чём урок уже говорит, но стоит подчеркнуть цифрами: спред
поверхностный. Глубокую копию даёт `structuredClone(obj)` — встроенный, без
библиотек, понимает `Map`, `Set`, `Date` и циклы, но не умеет функции.

Источник: learn.javascript.ru/object-copy, MDN — structuredClone

#### Деструктуризация (`destructuring`)

**Массив и объект разбираются по-разному.** Деструктуризация объекта берёт
свойства по имени. Деструктуризация массива идёт через **протокол
итератора** — тот же, что у `for...of`. Отсюда то, что выглядит магией:

```js
const [first] = new Set([10, 20]);        // 10
const [a, b] = 'ой';                      // 'о', 'й'
const [[key, value]] = new Map([['x', 1]]);
```

И обратная сторона: обычный объект так разобрать нельзя — итератора у него
нет.

Ещё одна мелочь из стандарта: значение по умолчанию срабатывает только на
`undefined`, но не на `null`:

```js
const { a = 5 } = { a: null };   // null, а не 5
```

Это то же правило, что у параметров функции, и та же причина, по которой в
задаче `defaultTo` `null` пришлось обрабатывать отдельно.

Источник: learn.javascript.ru/destructuring-assignment

#### Map (`map`)

**Как Map сравнивает ключи.** Не через `===`, а по алгоритму SameValueZero.
Отличие ровно одно, но важное: `NaN` считается равным самому себе.

```js
const m = new Map();
m.set(NaN, 'да');
m.get(NaN);            // 'да' — хотя NaN !== NaN
```

Второе: `Map` держит ключи-объекты **сильной** ссылкой. Пока жива карта, жив
и ключ, даже если больше на него никто не ссылается — типичная причина
утечек в кэшах. Для таких случаев есть `WeakMap`: ключами могут быть только
объекты, ссылки слабые, перебрать содержимое нельзя (иначе результат зависел
бы от того, когда сработал сборщик мусора).

Когда что: `Map` — если ключи добавляются и удаляются часто или не являются
строками; обычный объект — если набор полей известен заранее и не меняется
(тогда работает механизм скрытых классов из урока «Объекты»).

Источник: learn.javascript.ru/map-set, learn.javascript.ru/weakmap-weakset

#### Set (`set`)

**Set — это Map без значений**, с тем же SameValueZero и тем же порядком
вставки при переборе. Из этого следует всё поведение: два разных объекта с
одинаковыми полями — два разных элемента, `NaN` добавится только один раз,
`+0` и `-0` считаются одним значением.

Что появилось недавно и о чём стоит знать: операции над множествами прямо в
языке.

```js
const a = new Set([1, 2, 3]);
const b = new Set([2, 3, 4]);
a.intersection(b);   // Set {2, 3}
a.difference(b);     // Set {1}
a.union(b);          // Set {1, 2, 3, 4}
```

Поддержка свежая, и это ещё один повод заглянуть в таблицу совместимости
перед применением.

Источник: learn.javascript.ru/map-set, MDN — Set methods

#### Дата и время (`date`)

**Три ловушки `Date`, две из которых уже стоили нам одного бага на этой
платформе.**

1. **Парсинг зависит от формата.** Строка `'2020-01-01'` по стандарту
   разбирается как **UTC**, а `'2020/01/01'` и `'1-1-2020'` — как **местное
   время**. Разница в часовом поясе может сдвинуть дату на сутки. Отсюда же
   бралась ошибка в задаче про возраст: `toISOString()` переводит в UTC, и
   день рождения уезжал на день назад.

2. **`getMonth()` считает с нуля, а `getDate()` — с единицы.** Наследие
   реализации Java 1995 года. Рядом живёт `getDay()` — день недели, а не
   число месяца; их путают постоянно.

3. **Время нельзя брать из окружения.** `new Date()` даёт момент, но все
   геттеры (`getHours`, `getDate`) отдают его в поясе того, кто выполняет
   код. На сервере в UTC и на машине в Москве это разные сутки. Правильно —
   задавать пояс явно через `Intl.DateTimeFormat` с опцией `timeZone`; ровно
   это сделано в `src/lib/datetime.ts` этой платформы.

Всё это должен починить **`Temporal`** — новый встроенный API, который
разделяет «момент времени», «дату без времени» и «время с поясом», и в
котором месяцы наконец с единицы. Он уже появляется в браузерах.

Источник: learn.javascript.ru/date, MDN — Temporal, MDN — Intl.DateTimeFormat

#### Наследование и цепочка прототипов (`prototype-chain`)

**Как движок ищет свойство и почему цепочка почти ничего не стоит.** При
чтении `obj.x` движок смотрит форму объекта, не находит `x`, переходит по
`[[Prototype]]` и так далее до `null`. Наивно это выглядело бы медленно —
но результат поиска кэшируется в самом месте вызова (inline cache): «для
объектов такой формы `x` лежит там-то». Второй и последующие проходы идут
одним шагом.

Ломается кэш, когда в одном месте встречаются объекты разных форм. Отсюда
совет: не менять прототип объекта после создания. `Object.setPrototypeOf`
на живом объекте в V8 переводит его в медленный режим и сбрасывает кэши —
MDN про это пишет прямым текстом, что операция «очень медленная».

И приём, которым стоит пользоваться: `Object.create(null)` создаёт объект
вообще без прототипа. У него нет `toString`, нет `hasOwnProperty` — и нет
`__proto__`, а значит, его можно безопасно использовать как словарь для
ключей, пришедших от пользователя.

Источник: learn.javascript.ru/prototype-inheritance, v8.dev/blog/fast-properties

#### Функции-конструкторы (`constructor-functions`)

**Что делает `new`, по шагам.** Создаётся пустой объект; его
`[[Prototype]]` становится значением `Constructor.prototype` (а если там не
объект — `Object.prototype`); конструктор вызывается с этим объектом в
`this`; возвращается объект — **кроме случая, когда конструктор сам вернул
объект**, тогда возвращается он.

```js
function Weird() {
  this.a = 1;
  return { b: 2 };
}
new Weird();       // { b: 2 } — а не { a: 1 }
```

Примитив, возвращённый из конструктора, игнорируется. Это не курьёз: на этом
приёме строят конструкторы-фабрики, которые отдают закэшированный экземпляр.

Отличить вызов через `new` от обычного можно встроенным `new.target`: внутри
конструктора он равен самой функции, при обычном вызове — `undefined`.
Именно так библиотеки пишут «работает и с `new`, и без».

Источник: learn.javascript.ru/constructor-new

#### Контекст this и управление вызовом (`this-call-apply-bind`)

**`bind` создаёт не обёртку, а особый объект.** По стандарту результат
`bind` — экзотическая связанная функция с внутренними слотами
`[[BoundTargetFunction]]`, `[[BoundThis]]` и `[[BoundArguments]]`. Отсюда
поведение, которое кажется странным:

```js
function f() { return this.name; }
const once = f.bind({ name: 'первый' });
const twice = once.bind({ name: 'второй' });
twice();   // 'первый' — второй bind контекст не переопределяет
```

Причина: второй `bind` привязывает уже связанную функцию, а у неё контекст
зафиксирован внутри и наружу не выставлен.

Второе следствие: у связанной функции нет свойства `prototype`, а `name`
становится `'bound f'`. Поэтому `instanceof` через связанный конструктор
работает, а прямое обращение к `prototype` — нет.

Источник: learn.javascript.ru/bind, MDN — Function.prototype.bind

#### Object.create и методы прототипов (`object-create`)

**Дескрипторы и их коварные значения по умолчанию.** Свойство — это не
просто «имя и значение», а запись с четырьмя полями: `value`, `writable`,
`enumerable`, `configurable` (или `get`/`set` вместо первых двух).

Ловушка в том, что при создании через `defineProperty` и `Object.create`
все три флага по умолчанию **`false`**, а при обычном присваивании —
`true`:

```js
const a = {}; a.x = 1;
Object.getOwnPropertyDescriptor(a, 'x');
// { value: 1, writable: true, enumerable: true, configurable: true }

const b = Object.create(null, { x: { value: 1 } });
Object.getOwnPropertyDescriptor(b, 'x');
// { value: 1, writable: false, enumerable: false, configurable: false }
```

Именно поэтому в вашей задаче `object-create-polyfill` проверка на
`enumerable` даёт `false` во втором случае — это не ошибка проверки, а
стандарт.

`configurable: false` — единственный необратимый флаг: свойство после этого
нельзя ни удалить, ни переопределить. На этом стоят «замороженные» объекты.

Источник: learn.javascript.ru/property-descriptors

#### ES6-классы (`classes`)

**Класс — сахар, но не полностью.** Пять отличий от функции-конструктора,
которые описаны в стандарте отдельно:

1. Тело класса всегда в строгом режиме, даже если файл — нет.
2. Класс нельзя вызвать без `new` — будет `TypeError`.
3. Методы неперечисляемы: `for...in` и `Object.keys` их не увидят.
4. Объявление класса не поднимается так, как функция: до строки объявления
   оно в мёртвой зоне.
5. Приватные поля `#x` — **не свойства**. Это отдельный механизм приватных
   имён: их не видит ни `Object.keys`, ни `getOwnPropertyNames`, ни
   `Proxy`. Проверить наличие можно только особой формой: `#x in obj`.

Пятый пункт объясняет, почему `#private` — настоящая приватность, в отличие
от соглашения `_private`, которое просто просьба не трогать.

Источник: learn.javascript.ru/class, learn.javascript.ru/private-protected-properties-methods

#### prototype и \_\_proto\_\_ (`prototype-vs-proto`)

**`__proto__` — не свойство, а геттер-сеттер, и он в приложении к
стандарту.** Формально это аксессор, определённый в `Object.prototype`, и
описан он в Приложении B — разделе «нормативно, но только ради
совместимости с уже написанным вебом». Из этого следуют две вещи.

Первая: у объекта без прототипа `__proto__` вообще нет.

```js
const dict = Object.create(null);
dict.__proto__ = { admin: true };
Object.getPrototypeOf(dict);   // null — записалось обычное свойство
```

Вторая, гораздо важнее: если разобрать JSON от пользователя и слить его в
обычный объект, ключ `__proto__` попадёт **в сеттер**, и его значение
станет прототипом. Это и есть **загрязнение прототипа** (prototype
pollution) — целый класс уязвимостей, из-за которого чинили `lodash.merge`
и десятки других библиотек. Защита: `Object.create(null)` для словарей,
`Map` вместо объекта или явная проверка ключа перед записью.

Правильные инструменты — `Object.getPrototypeOf` и `Object.setPrototypeOf`;
`__proto__` в новом коде не используют вовсе.

Источник: learn.javascript.ru/prototype-methods, MDN — Object.prototype.\_\_proto\_\_

### Блок 3 · Обработка ошибок и асинхронность

#### try…catch и finally (`try-catch`)

**`finally` сильнее `return`.** Блок `finally` выполняется всегда, в том
числе между вычислением `return` и фактическим выходом. Если в нём тоже есть
`return`, он **побеждает**:

```js
function f() {
  try { return 'из try'; }
  finally { return 'из finally'; }
}
f();   // 'из finally'
```

Так же `finally` проглотит и брошенную ошибку. Поэтому `return` и `throw`
внутри `finally` — почти всегда ошибка; линтеры на это ругаются отдельным
правилом.

Второе: `catch` может быть без параметра — `catch { }` — если объект ошибки
не нужен. И третье, из свежего: у ошибки есть штатное поле для причины,
не нужно изобретать своё:

```js
throw new Error('Не удалось сохранить профиль', { cause: original });
```

`cause` печатается в консоли вместе со стеком исходной ошибки — то самое,
что в вашей задаче `apply-functions` делается вручную.

Источник: learn.javascript.ru/try-catch, MDN — Error.cause

#### Ошибки на границе данных (`data-boundaries`)

**У `JSON.parse` и `JSON.stringify` есть второй аргумент, и он решает
половину задач.** `parse` принимает функцию-оживитель (reviver), которая
вызывается для каждой пары и может преобразовать значение:

```js
JSON.parse(text, (key, value) =>
  key === 'createdAt' ? new Date(value) : value);
```

Это штатный способ восстановить даты, которых в JSON нет как типа.

`stringify` принимает заменитель (replacer) — функцию или список ключей.
Список ключей — самый короткий способ не отправить лишнее:

```js
JSON.stringify(user, ['id', 'name']);   // только эти два поля
```

И третий механизм — метод `toJSON`: если он есть у объекта, `stringify`
берёт его результат. Именно так `Date` превращается в строку ISO, и точно
так же можно научить свой класс сериализоваться правильно.

Источник: learn.javascript.ru/json

#### Собственные ошибки и повторные попытки (`custom-errors`)

**Почему приходится писать `this.name` руками.** Свойство `name` берётся из
прототипа, и у `Error.prototype` оно равно `'Error'`. Наследник своего
`name` не заводит — значит, наследует чужое. Отсюда строчка
`this.name = 'ValidationError'` в каждом классе; альтернатива, которая
работает и для наследников наследников:

```js
class AppError extends Error {
  constructor(message, options) {
    super(message, options);
    this.name = new.target.name;   // имя того класса, который вызвали через new
  }
}
```

Вторая деталь: если код собирается в ES5 (старые сборки, старые
транспиляторы), наследование от встроенных классов ломается, и
`instanceof` перестаёт работать. Лечится строкой
`Object.setPrototypeOf(this, new.target.prototype)` в конструкторе. Сегодня
это редкость, но узнать симптом полезно: «мой класс ошибки не проходит
`instanceof`» — почти всегда именно это.

Источник: learn.javascript.ru/custom-errors

#### Асинхронность и callback-функции (`callbacks`)

**Настоящая проблема колбэков — не «лесенка», а инверсия управления.**
Отдавая функцию чужому коду, вы отдаёте ему право решать, вызвать её или
нет, один раз или пять, сразу или через час, с ошибкой или без. Проверить
это никак нельзя — остаётся верить.

Промис — это в первую очередь **гарантии**, а не синтаксис: он переходит в
конечное состояние ровно один раз, обработчик вызывается ровно один раз, и
вызывается он всегда асинхронно, даже если результат уже готов. Именно
поэтому промисы заменили колбэки, а не потому, что `.then` короче.

Заодно: соглашение Node.js `callback(err, result)` — тоже попытка навести
порядок, но она держится только на дисциплине. Ошибка, брошенная **внутри**
колбэка, ни в какой `try...catch` снаружи не попадёт — стек к этому моменту
уже другой.

Источник: learn.javascript.ru/callbacks

#### Промисы и их композиция (`promises`)

**`then` всегда откладывает вызов, даже если промис уже разрешён.** Это
записано в стандарте: обработчик ставится в очередь микрозадач. Поэтому

```js
Promise.resolve(1).then(console.log);
console.log(2);
// 2, потом 1
```

Гарантия нужна, чтобы код был предсказуемым: обработчик никогда не
выполняется «иногда синхронно, иногда нет».

Второе: `await` и `then` работают не только с промисами, а с любым
**thenable** — объектом, у которого есть метод `then`. Отсюда совместимость
со старыми библиотеками промисов и отсюда же редкий баг: объект со
случайным полем `then` в асинхронном коде ведёт себя странно.

И третье, из практики: у отклонённого промиса без `.catch` есть шанс быть
замеченным — браузер бросает событие `unhandledrejection`. Его стоит
слушать в проде, иначе часть ошибок исчезает бесследно.

Источник: learn.javascript.ru/promise-basics, learn.javascript.ru/microtask-queue

#### Async и await (`async-await`)

**`async function` — это генератор с автозапуском.** Компилятор превращает
её в конечный автомат: каждый `await` — точка приостановки, где функция
подписывается на промис и возвращает управление, а при разрешении
продолжает с того же места. Локальные переменные при этом сохраняются в
объекте состояния, а не на стеке.

Отсюда следствие, которое ловят на собеседованиях: `await` **всегда** даёт
минимум один тик микрозадачи, даже если справа не промис.

```js
async function f() { console.log(1); await null; console.log(3); }
f(); console.log(2);
// 1, 2, 3
```

И второе: `try...catch` вокруг `await` работает потому, что приостановка и
возобновление происходят внутри той же функции — а вот `try...catch` вокруг
`.then(...)` не поймает ничего, там стек уже другой. Это главный
практический аргумент в пользу `async/await`.

Источник: learn.javascript.ru/async-await

#### Event Loop, throttle и debounce (`event-loop`)

**Микрозадачи опустошаются полностью — и в этом опасность.** Цикл событий
берёт одну макрозадачу (таймер, событие, сетевой ответ), выполняет её, а
потом разбирает очередь микрозадач **до конца**, включая те, что появились
по дороге. Если микрозадача плодит новую микрозадачу, страница подвиснет
навсегда, и ни один таймер не сработает:

```js
function loop() { Promise.resolve().then(loop); }
loop();   // вкладка мертва, хотя цикла for нет
```

Тот же код на `setTimeout` не подвесит ничего — таймеры это макрозадачи, и
между ними браузер успевает отрисовать кадр.

Отрисовка, кстати, — отдельная фаза, и попасть в неё ровно перед кадром
можно через `requestAnimationFrame`. Для анимаций это правильный
инструмент, а `setTimeout(fn, 16)` — приближение, которое рассинхронизуется.

Поставить свою микрозадачу напрямую можно через `queueMicrotask` — без
создания промиса ради `then`.

Источник: learn.javascript.ru/event-loop, MDN — queueMicrotask

### Блок 4 · Browser API и HTTP

#### Введение в DOM (`dom-intro`)

**Живые и статические коллекции.** `querySelectorAll` возвращает статический
`NodeList` — снимок на момент вызова. А `getElementsByClassName`,
`getElementsByTagName` и свойство `children` возвращают **живые**
коллекции: они пересчитываются сами при изменении документа. Отсюда
классический баг:

```js
const items = document.getElementsByClassName('item');
for (let i = 0; i < items.length; i += 1) items[i].remove();
// удалится половина: коллекция сокращается на каждом шаге
```

С `querySelectorAll` того же кода не случится. Правило: если коллекцию
перебирают и меняют документ — берите `querySelectorAll` или сначала
копируйте в массив через `Array.from`.

Источник: learn.javascript.ru/searching-elements-dom, MDN — NodeList

#### Атрибуты и свойства (`dom-attributes`)

**Синхронизация не всегда двусторонняя.** Для большинства стандартных
атрибутов браузер держит атрибут и свойство в паре. Но у поля ввода это
устроено иначе: атрибут `value` задаёт только **начальное** значение и
доступен как `input.defaultValue`, а свойство `input.value` живёт своей
жизнью.

```js
input.value = 'напечатано';
input.getAttribute('value');   // прежнее, из разметки
```

Поэтому сброс формы возвращает поле к атрибуту, а не к тому, что там было.

Собственные данные держат в `data-*` — не из вежливости, а потому что
стандарт гарантирует: атрибут с этим префиксом никогда не станет
стандартным и ни с чем не столкнётся. Доступ к ним через `dataset`, и имя
преобразуется: `data-user-id` становится `dataset.userId`.

Источник: learn.javascript.ru/dom-attributes-and-properties

#### Изменение документа (`dom-modify`)

**Почему перерисовка списка целиком — не расточительство.** Изменение DOM
не рисует ничего сразу: браузер копит правки и пересчитывает раскладку
(reflow) один раз перед кадром. Но если между записями **прочитать**
геометрию — `offsetHeight`, `getBoundingClientRect`, `scrollTop` — браузер
обязан пересчитать всё немедленно, чтобы ответить честно. Чередование
записи и чтения в цикле называют «пробуксовкой раскладки» (layout
thrashing), и это одна из главных причин тормозящих интерфейсов.

```js
for (const el of items) {
  el.style.height = el.offsetHeight + 10 + 'px';   // чтение после записи — reflow на каждой итерации
}
```

Лечение: сначала все чтения, потом все записи. Или собрать узлы в
`DocumentFragment` и вставить одним `append` — фрагмент не в документе, и
его изменения ничего не пересчитывают.

Источник: MDN — DocumentFragment, learn.javascript.ru/modifying-document

#### События (`dom-events`)

**У `addEventListener` есть третий аргумент, и он полезнее, чем кажется.**

```js
el.addEventListener('click', handler, {
  once: true,       // снять после первого срабатывания
  passive: true,    // обещание не вызывать preventDefault
  signal: controller.signal,  // снять вместе с AbortController
  capture: true,    // слушать фазу погружения
});
```

`passive` — не оптимизация «на всякий случай»: без него браузер при
прокрутке обязан **дождаться** вашего обработчика, чтобы узнать, не
отмените ли вы прокрутку. Отсюда «залипающий» скролл на мобильных. Для
`touchstart`, `touchmove` и `wheel` на документе браузеры уже включают
`passive` по умолчанию.

`signal` — самый удобный способ снять сразу все обработчики компонента:
один `controller.abort()` вместо десяти `removeEventListener` с
сохранёнными ссылками.

Источник: learn.javascript.ru/introduction-browser-events, MDN — EventTarget.addEventListener

#### Событийная модель (`dom-event-model`)

**Три фазы существуют для всех событий, но не все всплывают.** `focus`,
`blur`, `load` и `mouseenter` не всплывают вовсе — для них делегирование не
работает. У `focus` есть всплывающий двойник `focusin`, у `mouseenter` —
`mouseover`; это стандартный обход.

Второе: `stopPropagation` останавливает подъём выше, но соседние
обработчики **на том же элементе** всё равно отработают. Остановить и их
может только `stopImmediatePropagation`.

И третье, полезное на практике: `event.isTrusted` показывает, породил
событие пользователь или скрипт через `dispatchEvent`. Разница не
косметическая: запрос разрешения на уведомления или камеру, открытие окна
без блокировщика, полноэкранный режим — всё это браузер выполняет только
в ответ на настоящий пользовательский жест. Синтетический клик из скрипта
эти двери не открывает.

Источник: learn.javascript.ru/bubbling-and-capturing, learn.javascript.ru/event-delegation

#### Local Storage (`local-storage`)

**`localStorage` синхронный, и это его главный недостаток.** Каждое чтение и
запись блокируют главный поток: пока идёт обращение к диску, страница не
отвечает. На большом объёме это заметно. Ограничение — около 5 МБ на
источник, при превышении будет `QuotaExceededError` (и он же прилетит в
приватном режиме Safari, где квота нулевая) — поэтому запись стоит
оборачивать в `try...catch`.

Полезное, о чём мало кто знает: при изменении хранилища браузер бросает
событие `storage` **в других вкладках** того же источника, но не в той,
которая изменила. Это готовый механизм синхронизации вкладок:

```js
window.addEventListener('storage', (event) => {
  if (event.key === 'theme') applyTheme(event.newValue);
});
```

Для больших и структурированных данных есть асинхронная `IndexedDB`, а для
обмена между вкладками без хранилища — `BroadcastChannel`.

Источник: learn.javascript.ru/localstorage, MDN — Window: storage event

#### Основы AJAX (`ajax-basics`)

**Откуда всё пошло.** `XMLHttpRequest` придумали в Microsoft для
веб-версии Outlook в 1999 году; название с «XML» приклеилось случайно и
пережило сам формат. Термин «AJAX» появился только в 2005-м, в статье о
том, как устроены Google Maps и Gmail, — то есть подход существовал
шесть лет без имени.

Что `XMLHttpRequest` умеет, а `fetch` — нет: события прогресса загрузки
(`upload.onprogress`), то есть честный индикатор отправки большого файла.
В `fetch` прогресс **скачивания** читается через потоки
(`response.body.getReader()`), а прогресс отправки в браузерах до сих пор
не везде доступен. Поэтому загрузчики файлов иногда до сих пор пишут на
`XMLHttpRequest` — это не легаси, а осознанный выбор.

Источник: learn.javascript.ru/xmlhttprequest, MDN — XMLHttpRequest

#### Методы запросов (`ajax-requests`)

**Стандарт делит методы по двум независимым признакам.** *Безопасный*
(safe) — не меняет состояние на сервере: `GET`, `HEAD`, `OPTIONS`, `TRACE`.
*Идемпотентный* — можно повторить без изменения результата: все безопасные
плюс `PUT` и `DELETE`. `POST` и `PATCH` не входят ни туда, ни туда.

Практическое применение прямое: браузеры, прокси и клиентские библиотеки
автоматически повторяют только идемпотентные запросы после обрыва связи.
Если вашему `POST` нужна защита от повтора, её делают явно — ключом
идемпотентности в заголовке; так устроены все платёжные API.

Второе: браузер не отправляет «сложный» межсайтовый запрос сразу. Сначала
уходит **предварительный** `OPTIONS` со списком метода и заголовков, и
только после разрешения — сам запрос. «Простыми» считаются `GET`, `HEAD` и
`POST` с несколькими разрешёнными типами содержимого; `Content-Type:
application/json` в этот список **не входит**, поэтому обычный JSON-запрос
на чужой домен всегда идёт с предварительной проверкой.

Источник: MDN — Методы HTTP-запроса, MDN — CORS preflight

#### Отладка запросов и статус-коды (`ajax-debug`)

**Колонка Waterfall во вкладке Network читается по стадиям.** «Queued» —
запрос ждёт свободного соединения; «Stalled» — то же, но по другим
причинам; «DNS Lookup» и «Initial connection» — установка соединения;
«Waiting (TTFB)» — время до первого байта, то есть работа сервера;
«Content Download» — скачивание тела. Разница между медленным сервером и
медленной сетью видна сразу: в первом случае большой TTFB, во втором —
большой Content Download.

И различие, которое стоит знать про перенаправления: `301`/`302` браузеры
исторически превращают `POST` в `GET` при переходе, а `307`/`308` —
сохраняют метод и тело. Поэтому «форма отправилась, а данные не дошли»
почти всегда означает `302` в цепочке.

Источник: MDN — Коды состояния HTTP

#### Fetch (`fetch`)

**Тело ответа можно прочитать только один раз.** `response.json()` забирает
поток; второй вызов бросит ошибку, а `response.bodyUsed` покажет `true`.
Если ответ нужен дважды (например, залогировать и разобрать), сначала
делают `response.clone()`.

**Про CORS без мифов.** Ограничение накладывает браузер, а не сервер.
Запрос уходит, сервер его выполняет, ответ приходит — и браузер **не даёт
его прочитать**, если в ответе нет `Access-Control-Allow-Origin`. Отсюда
две вещи: во-первых, CORS не защищает сервер (curl и любой бэкенд ходят без
ограничений), во-вторых, `mode: 'no-cors'` не «обходит» CORS — он даёт
непрозрачный (opaque) ответ, у которого статус 0 и тело недоступно.

**Отмена.** У `fetch` нет `abort()`, есть `AbortController`:

```js
const controller = new AbortController();
fetch(url, { signal: controller.signal });
controller.abort();   // промис отклонится с AbortError
```

Это ровно то, что нужно для автодополнения: при новом вводе предыдущий
запрос отменяют, иначе ответы могут прийти не в том порядке и затереть
свежие результаты старыми.

Источник: learn.javascript.ru/fetch, learn.javascript.ru/fetch-crossorigin, learn.javascript.ru/fetch-abort

#### Как работает интернет (`how-internet-works`)

**Что изменилось с HTTP/2 и HTTP/3.** В HTTP/1.1 на одном соединении шёл
один запрос за раз, поэтому фронтенд склеивал файлы, спрайтил картинки и
шардил домены — всё ради обхода лимита в шесть соединений.

HTTP/2 сделал протокол бинарным и мультиплексным: десятки запросов идут
параллельно по одному соединению, а заголовки сжимаются (HPACK) — на них
приходилось до половины трафика мелких запросов. Большая часть старых
приёмов оптимизации после этого стала вредной.

HTTP/3 переехал с TCP на QUIC поверх UDP. Смысл в том, что в TCP потеря
одного пакета останавливает **все** потоки в соединении (head-of-line
blocking), а в QUIC — только свой. Плюс соединение переживает смену сети:
переход с Wi-Fi на мобильный не рвёт загрузку.

Источник: MDN — Эволюция HTTP

#### Протокол DNS (`dns`)

**DNS — это не только имя в адрес.** Типы записей, которые встречаются в
работе: `A` (IPv4), `AAAA` (IPv6), `CNAME` (псевдоним другого имени),
`MX` (почтовые серверы), `TXT` (произвольный текст — им подтверждают права
на домен и настраивают почтовые подписи), `NS` (кто отвечает за зону).

Иерархия: рекурсивный сервер (провайдера или публичный вроде 8.8.8.8)
опрашивает корневой сервер, затем сервер зоны `.ru`, затем авторитативный
сервер домена. Ответы кэшируются на время TTL, и уменьшать TTL заранее — 
стандартная подготовка к переезду.

Посмотреть своими глазами: `nslookup example.com` или `dig example.com A`
в терминале. Полезно при разборе «у меня сайт открывается, а у клиента
нет».

И новое: DNS исторически ходит открытым текстом, поэтому провайдер видит,
какие сайты вы открываете. Это решают DNS over HTTPS и DNS over TLS —
браузеры их уже используют.

Источник: guides.hexlet.io/dns, MDN — DNS

#### Протокол HTTP (`http`)

**Кэширование — самая полезная часть заголовков.** Сервер отдаёт `ETag` —
отпечаток содержимого. При следующем запросе браузер шлёт
`If-None-Match: <тот же ETag>`, и если ничего не изменилось, сервер
отвечает `304 Not Modified` **без тела**. Экономится не соединение, а
трафик.

`Cache-Control` управляет тем, будет ли запрос вообще: `max-age=3600` —
не спрашивать час, `no-cache` — спрашивать всегда, но можно отдать
кэшированное после 304, `no-store` — не хранить вовсе (для страниц с
персональными данными).

И про «HTTP не хранит состояние»: это свойство сделало возможным
масштабирование. Раз сервер не помнит клиента, любой запрос может обработать
любой из ста серверов — отсюда балансировщики и горизонтальное
масштабирование. Всё, что «помнится», лежит либо у клиента (кука, токен),
либо в общем хранилище, но не в самом соединении.

Источник: learn.javascript.ru/fetch-crossorigin, MDN — HTTP-кэширование

#### Что такое API (`api`)

**Договор должен быть машинночитаемым, иначе он рассыпается.** Для HTTP-API
такой формат — **OpenAPI** (раньше Swagger): YAML или JSON, где описаны
адреса, методы, схемы запросов и ответов. По этому файлу генерируются
документация, клиентские библиотеки на любом языке и тесты, которые
проверяют, что сервер отвечает по схеме.

Отсюда практическое: если у сервиса есть OpenAPI-файл, ходить в него руками
и писать типы вручную не нужно.

Вторая половина договора — **правила изменения**. Обратно совместимо:
добавить поле в ответ, добавить необязательный параметр. Несовместимо:
удалить поле, переименовать, сделать необязательное обязательным, сузить
диапазон значений. Ровно эта граница и определяет, повышать ли мажорную
версию.

Источник: MDN — Введение в веб-API

#### REST (`rest`)

**Уровни зрелости (модель Ричардсона).** Уровень 0 — один адрес, всё через
`POST` (так работает RPC). Уровень 1 — появились ресурсы: `/users`,
`/orders`. Уровень 2 — методы используются по смыслу и статус-коды тоже:
201 на создание, 404 на отсутствие. Уровень 3 — HATEOAS: ответ содержит
ссылки на возможные следующие действия, и клиент ходит по ним, а не по
захардкоженным адресам.

Полезно знать, что почти всё, что в индустрии называют REST, — это
уровень 2. Уровень 3 в жизни встречается редко, и споры «а это настоящий
REST?» обычно как раз об этом.

Чем отличается **GraphQL**: там один адрес и один метод, а форму ответа
задаёт клиент в запросе. Решает проблему «пришло слишком много полей» и
«пришлось сделать пять запросов вместо одного», но платит кэшированием —
браузерный кэш по адресу тут не работает.

Источник: habr.com — REST простым языком, ymatuhin.ru — RESTful API для фронтендера

#### Тестирование запросов (`request-testing`)

**Быстрее Postman — прямо в браузере.** У любого запроса во вкладке Network
есть контекстное меню «Copy → Copy as fetch» и «Copy as cURL». Это
готовый, работающий код со всеми заголовками и куками, который можно
вставить в консоль или в терминал и менять по одному параметру. Приём
экономит больше времени, чем любой отдельный клиент: вы начинаете не с
чистого листа, а с запроса, который точно работает.

Обратный ход тоже полезен: `curl` из документации API вставляется в Postman
через «Import → Raw text», и получается готовый запрос с заполненными
полями.

И третий инструмент, который часто ближе всего: файлы `.http` / `.rest`
прямо в редакторе (VS Code, JetBrains). Запрос лежит рядом с кодом, в
репозитории, и обновляется вместе с ним.

Источник: MDN — Инструменты разработчика, вкладка Сеть

#### Хранение данных на клиенте (`client-storage`)

**Атрибуты куки — это и есть вся её безопасность.**

- `HttpOnly` — куку не видит JavaScript. Единственная реальная защита
  сессии от XSS: даже если чужой скрипт выполнится, украсть сессию он не
  сможет.
- `Secure` — только по HTTPS.
- `SameSite` — отправлять ли куку при переходе с чужого сайта. `Strict` —
  никогда, `Lax` — только при обычных переходах по ссылке, `None` — всегда,
  но тогда обязателен `Secure`. Если атрибут не указан, Chrome и Edge
  подставляют `Lax` сами; Safari и Firefox приходят к тому же другими
  путями.

Переход браузеров на `SameSite=Lax` по умолчанию в 2020 году одним махом
закрыл большую часть CSRF-атак — и заодно сломал множество виджетов,
встроенных через iframe. Это хороший пример того, как решение по умолчанию
меняет отрасль сильнее, чем новая возможность.

И итог урока цифрами: кука — до 4 КБ и уезжает на сервер с каждым запросом;
`localStorage` — около 5 МБ и не уезжает никогда. Держать в куке
пользовательские настройки — значит платить за них трафиком на каждой
картинке.

Источник: learn.javascript.ru/cookie, MDN — Set-Cookie

#### Проектные уроки (`github-autocomplete-review`, `auth-to-api-review`)

Для проектных уроков «под капотом» стоит писать не про язык, а про
инструмент, с которым столкнётся ученик:

- **GitHub API** ограничивает неавторизованные запросы шестьюдесятью в час
  на IP-адрес. Остаток виден в заголовках ответа `X-RateLimit-Remaining` и
  `X-RateLimit-Reset`. Отсюда сразу два вывода для задачи: во-первых,
  `debounce` — не украшение, а необходимость; во-вторых, при 403 нужно
  показывать человеку, что лимит исчерпан, а не «что-то пошло не так».
  Это же отличный повод один раз посмотреть в настоящую документацию
  большого API.

- **JWT** состоит из трёх частей, разделённых точками: заголовок, полезная
  нагрузка и подпись. Первые две — это **base64url, а не шифрование**:
  содержимое токена может прочитать кто угодно, вставив его на jwt.io.
  Подпись гарантирует только то, что токен не подделан. Отсюда правило:
  в токен не кладут ничего секретного, а срок жизни делают коротким, потому
  что отозвать выданный токен нельзя — только дождаться истечения.

Источник: docs.github.com — REST API rate limits, MDN — HTTP-аутентификация

#### Уроки «Запись на ревью» (`module-checklist`, `review-booking`)

Здесь «звёздочка» уместна другая — не про язык, а про профессию: **как
проходит код-ревью в команде**. Что смотрят в первую очередь (не стиль, а
границы: что будет при пустом вводе, при ошибке сети, при повторном
вызове), почему комментарий «почему так, а не иначе» полезнее, чем
«перепиши», и почему на ревью приносят маленькие изменения — большие
никто не читает внимательно.

Это заодно снимет тревогу перед самим ревью: ученик поймёт, что его код
будут не оценивать, а обсуждать.

## 7. Новый блок: «Как читать документацию»

### Зачем и почему именно на этой платформе

Навык читать документацию отличается от остальных тем, что его нельзя
проверить рассказом. Ученик, который «понял, как читать MDN», и ученик,
который не понял, на словах отвечают одинаково. Разница видна только тогда,
когда перед ними задача, **которую невозможно решить по памяти**.

И вот тут у платформы есть то, чего нет у книжек и видеокурсов: раннер,
который выполняет код ученика в браузере. Значит, можно дать задачу,
решаемую только через встроенный API, которого никто не помнит наизусть, —
и ученик физически вынужден открыть документацию, найти нужную опцию и
понять, что она делает. Это и есть проверка навыка.

Второе, что делает блок ценным именно здесь: в курсе уже **71 ссылка** на
внешние источники, и распределены они так:

| Источник | Ссылок |
|---|---|
| learn.javascript.ru | 52 |
| habr.com | 7 |
| developer.mozilla.org (MDN) | 6 |
| остальные (Hexlet, Skillbox, Medium, GitHub Docs, блоги) | 6 |

Три четверти курса опираются на один учебник. Это не упрёк — учебник
отличный, — но означает, что ученик выходит с курса, ни разу толком не
поработав со справочником. А в работе всё наоборот: learn.javascript.ru
кончается там, где начинается настоящая задача, и дальше только MDN и
стандарты. Блок закрывает ровно этот разрыв — и заодно объясняет то, чем
курс и так пользуется, но никогда не объяснял: почему на MDN есть таблица
поддержки, а на Хабре нет.

#### Модуль 1. «Где искать и чему верить» (4 урока)

**Урок 1.1. Три источника правды**

Текст урока. Есть три уровня, и путать их дорого.

*Спецификация* (ECMA-262 для языка, стандарты WHATWG для DOM и HTML,
RFC для сетевых протоколов) — это то, что производители браузеров обязались
реализовать. Она отвечает на вопрос «как должно быть», написана предельно
точно и предельно сухо. В неё идут, когда поведение непонятно и спорно.

*Справочник* (MDN) — та же информация, переведённая на человеческий, с
примерами и, главное, с таблицей поддержки в браузерах. Отвечает на вопрос
«как этим пользоваться». Это рабочая лошадка: 90% обращений — сюда.

*Учебники и статьи* (learn.javascript.ru, Хабр, блоги) — объясняют «зачем
и почему», связывают вещи между собой. Незаменимы, когда тема новая. Но у
них есть дата, и она не всегда видна.

Правило, которое стоит вынести из урока: **чем конкретнее вопрос, тем выше
по списку идти**. «Что такое замыкание» — учебник. «Что вернёт `slice` с
отрицательным индексом» — справочник. «В каком порядке вызываются `valueOf`
и `toString`» — спецификация.

Отдельный абзац — про Stack Overflow и нейросети. И то, и другое даёт
ответ мгновенно и без источника. Ответ 2013 года с сотней плюсов может быть
неверным сегодня; ответ модели может быть вымышленным. Проверка одна и та
же: найти это же утверждение в справочнике.

Задача: **quiz `docs-source-choice`** (см. ниже).

**Урок 1.2. Анатомия страницы MDN**

Текст урока: разбор страницы `Array.prototype.slice` по частям, сверху вниз.

1. Одно предложение сверху — что метод делает. Часто этого достаточно.
2. **Syntax** — все формы вызова. Здесь квадратные скобки означают
   «необязательный», многоточие — «сколько угодно».
3. **Parameters** — что можно передать, включая случай «не передан».
4. **Return value** — что вернётся, и **мутирует ли исходное значение**.
   Это самая пропускаемая строка и источник половины ошибок.
5. **Exceptions** — когда бросит.
6. **Examples** — читать снизу вверх: интересные случаи внизу.
7. **Specifications** — ссылка в стандарт.
8. **Browser compatibility** — таблица.
9. **See also** — почти всегда там лежит то, что вы на самом деле искали.

Ключевая мысль урока: **на MDN не читают страницу целиком**. Читают
заголовок, Return value и один пример. Полное чтение — признак того, что
вопрос сформулирован неточно.

Задача: **quiz `mdn-anatomy`**.

**Урок 1.3. Как читать сигнатуру**

Текст урока: словарь обозначений, который нигде не объясняют, потому что
«и так понятно».

```
arr.slice()
arr.slice(start)
arr.slice(start, end)
```

— три строки означают, что аргументы необязательные, и MDN пишет их
именно так, а не через квадратные скобки (старый стиль, ещё встречается).

```
fetch(resource, options)
```

— второй параметр объект, и его поля описаны отдельным списком ниже.

В TypeScript и в файлах `.d.ts` та же информация записывается плотнее:

```ts
slice(start?: number, end?: number): T[]
```

`?` — необязательный, `:` — тип, `|` — «или», `[]` — массив,
`T` — «тот же тип, что внутри». Читать `.d.ts` полезно и без TypeScript:
это самая честная и короткая документация к любой библиотеке.

Задача: **algorithm `slice-by-docs`**.

**Урок 1.4. Совместимость: можно ли это уже использовать**

Текст урока: как читать таблицу поддержки и метки статуса.

- **Baseline** — новая пометка на MDN. «Widely available» значит, что
  возможность поддерживается всеми основными браузерами больше 30 месяцев
  и её можно брать не задумываясь. «Newly available» — поддерживается
  везде, но недавно; проверьте, какие браузеры у ваших пользователей.
- **Deprecated** — работает, но не используйте в новом коде.
- **Experimental** — может измениться или исчезнуть.
- **Non-standard** — работает в одном браузере, стандартом не является.
- **Annex B** — раздел стандарта «нормативно, но только ради старого
  веба»: сюда попали `__proto__`, `escape`, `document.all`.

И практический вопрос, который надо задавать себе каждый раз: **у кого
именно этот код будет выполняться?** Внутренняя админка на Chrome и
публичный магазин с посетителями на пятилетних телефонах — разные ответы
на один и тот же вопрос о совместимости.

Задача: **quiz `docs-compat`**.

#### Модуль 2. «Первоисточники» (4 урока)

**Урок 2.1. Как устроена спецификация ECMA-262**

Текст урока: спецификация не страшная, она просто написана как алгоритм.

Разбор одного короткого алгоритма — `Array.prototype.includes`. Показать,
что «Let O be ? ToObject(this value)» читается как «преобразовать `this` в
объект, и если это бросит ошибку — прекратить». Объяснить обозначения:

- `[[Prototype]]`, `[[Call]]` — **внутренние слоты**: то, что есть у
  значения, но недоступно из кода.
- `?` перед вызовом — «если бросит ошибку, выйти отсюда же».
- `!` — «здесь ошибка невозможна».
- **Абстрактные операции** (`ToNumber`, `ToPrimitive`, `SameValueZero`) —
  внутренние функции спецификации; именно на них ссылаются, когда объясняют
  странности приведения типов.

Практический вывод: в спецификацию идут не читать, а **искать конкретный
ответ** — обычно поиском по имени метода. И читают оттуда пять строк.

Задача: **algorithm `to-number-by-spec`**.

**Урок 2.2. RFC и сетевые стандарты**

Текст урока: HTTP описан не на MDN, а в RFC 9110 (семантика) и RFC 9112
(синтаксис HTTP/1.1). У RFC свой язык обязательности, определённый в
RFC 2119:

- **MUST** / **REQUIRED** — обязано, иначе это не реализация протокола;
- **SHOULD** — следует, но можно отступить, понимая последствия;
- **MAY** — на усмотрение.

Разница между MUST и SHOULD в споре с бэкендом решает больше, чем любые
аргументы. Пример: «сервер MUST вернуть `Allow` при 405» — значит, отсутствие
заголовка это баг сервера, а не особенность.

Ориентиры: коды состояния — RFC 9110 §15; методы — §9; заголовки
кэширования — RFC 9111.

Задача: **algorithm `method-properties`**.

**Урок 2.3. README, CHANGELOG и версии**

Текст урока: как за пять минут решить, брать ли библиотеку.

- **README** — что делает, минимальный пример, установка. Если минимального
  примера нет — плохой знак.
- **CHANGELOG** — как часто выходят версии и что ломалось. Если последняя
  запись двухлетней давности, библиотека либо готова, либо заброшена, и это
  различают по числу открытых issue.
- **Семантические версии** `МАЖОРНАЯ.МИНОРНАЯ.ПАТЧ`: патч — исправление,
  минорная — новое без поломок, мажорная — ломающие изменения. Знаки в
  `package.json`: `^1.2.3` разрешает всё до 2.0.0, `~1.2.3` — только патчи,
  `1.2.3` — точно эту.
- **Issues** — искать по тексту своей ошибки **до** того, как чинить.
  Половина «странных багов» уже описана там же, вместе с обходным путём.

Задача: **algorithm `next-version`**.

**Урок 2.4. Когда документации нет**

Текст урока: три источника по убыванию удобства.

1. **Файлы типов `.d.ts`.** Лежат в пакете, читаются как оглавление: все
   функции, все аргументы, все типы. Быстрее любого README.
2. **Тесты библиотеки.** Самая честная документация: там записано, как
   автор ожидает, что его кодом будут пользоваться, и эти ожидания
   проверяются при каждой сборке. Искать в папке `test` или `__tests__`.
3. **Исходники.** Последний рубеж, но с одним приёмом: не читать подряд,
   а искать по имени функции и смотреть только её.

И отдельно про чужой код в проекте: перед тем как менять непонятную
функцию, найдите её тесты и историю в git — `git log -p путь/к/файлу`
часто объясняет «почему так» лучше любого комментария.

Задача: **algorithm `read-the-types`**.

#### Модуль 3. «Проверять, а не верить» (3 урока)

**Урок 3.1. Минимальный воспроизводимый пример**

Текст урока: главный навык отладки — уметь **уменьшать**. Взять код, где
ошибка, и выбрасывать из него всё, что можно выбросить, пока ошибка не
исчезнет. Последнее удаление и есть причина.

Тот же приём работает и с документацией: прочитали в справочнике
утверждение — проверьте его в консоли на трёх строках, прежде чем строить
на нём решение. Это занимает двадцать секунд и экономит час.

Задача: **algorithm `shrink-the-case`** (см. ниже) — единственная задача
блока, где ученику дают сложную функцию и просят найти минимальный вход,
на котором она ломается.

**Урок 3.2. Как задать вопрос**

Текст урока: структура, которая работает и в поиске, и в issue, и в
сообщении коллеге.

1. Что вы делали (минимальный пример кода).
2. Что ожидали получить.
3. Что получили на самом деле — точный текст ошибки, а не пересказ.
4. Окружение: версии, браузер, ОС.
5. Что вы уже попробовали.

Отдельно — как искать: в поиск идёт **текст ошибки без своих имён**.
`Cannot read properties of undefined (reading 'map')` найдётся,
`Cannot read properties of undefined (reading 'myUserList')` — нет.

Приём с обратной стороны: пока формулируете вопрос по этой схеме, ответ
находится сам примерно в половине случаев. Это не шутка, у явления есть
имя — «отладка резиновым утёнком».

Задача: **quiz `good-question`**.

**Урок 3.3. Документация как договор — и своя тоже**

Текст урока: если ваш код кто-то будет вызывать (а это всегда так, хотя бы
вы сами через полгода), у него есть документация — вопрос только в том,
написана она или нет.

Что писать в комментарии: **почему**, а не **что**. `// увеличиваем i на
единицу` — мусор. `// начинаем со второго элемента: первый — заголовок
таблицы` — то, что нельзя восстановить из кода.

JSDoc как минимальный формат:

```js
/**
 * Считает полные дни между датами.
 * @param {Date|string|number} first
 * @param {Date|string|number} second
 * @returns {number} NaN, если хотя бы одна дата невалидна
 * @throws {TypeError} если передан только один аргумент
 */
```

Это ровно то описание, которое вы бы хотели найти на MDN. Редакторы читают
JSDoc и показывают подсказки при вызове — то есть польза мгновенная.

Задача: **algorithm `document-the-function`** — ученику дают готовую
функцию с неочевидным поведением, он должен по её коду ответить на вопросы
о контракте (что вернёт при пустом вводе, бросит ли, мутирует ли). Проверки
сверяют ответы.

### Задачи блока: спецификации

Все укладываются в существующий раннер: `quiz` и `algorithm`. Ни одна не
требует новых возможностей платформы.

#### `docs-source-choice` — quiz, 5 вопросов

Ситуации, для каждой выбрать источник (спецификация / MDN / учебник /
исходники библиотеки):

- «Не помню, мутирует ли `sort`» → MDN, строка Return value.
- «Не понимаю, что такое замыкание» → учебник.
- «Спорим с коллегой, в каком порядке `+` приводит типы» → спецификация.
- «Метод из статьи 2019 года не работает» → MDN, таблица совместимости

- «Библиотека делает не то, что написано в README» → её тесты и issues.

#### `mdn-anatomy` — quiz, 4 вопроса

По приведённому в вопросе фрагменту страницы MDN найти ответ:
где написано, что метод мутирует; что означает `start` в квадратных
скобках; что значит «Baseline: Widely available»; куда смотреть, если
метод не работает в Safari.

#### `docs-compat` — quiz, 4 вопроса

Описания реальных ситуаций: внутренний инструмент для команды на Chrome;

скрипт для Node.js. Для каждой — можно ли брать «newly available».

#### `slice-by-docs` — algorithm

**Идея:** реализовать `mySlice(array, start, end)` **строго по описанию с
MDN**, включая все случаи, которые обычно не помнят.

Условие задачи — не пересказ, а прямая цитата поведения из справочника, и
ученику прямо сказано: откройте страницу `Array.prototype.slice` и
перенесите правила.

Проверки берут ровно те случаи, которые описаны в документации:

```js
mySlice([1,2,3,4,5], 1, 3)    // [2, 3]
mySlice([1,2,3,4,5], 2)       // [3, 4, 5] — end не передан
mySlice([1,2,3,4,5], -2)      // [4, 5] — отрицательный start
mySlice([1,2,3,4,5], 1, -1)   // [2, 3, 4] — отрицательный end
mySlice([1,2,3,4,5], 3, 1)    // [] — start больше end
mySlice([1,2,3,4,5], 0, 100)  // [1,2,3,4,5] — end за пределами
mySlice([1,2,3])              // [1,2,3] — копия
```

Плюс служебная проверка: исходный массив не изменился.

Смысл задачи: невозможно решить «по интуиции», отрицательные индексы и
`start > end` придётся посмотреть. И после неё ученик уже никогда не
перепутает `slice` со `splice`.

#### `to-number-by-spec` — algorithm

**Идея:** реализовать `toNumber(value)` — свой аналог `Number(value)` по
таблице приведения из спецификации, **не используя `Number()` и унарный
плюс**.

В условии — та самая таблица (её можно привести целиком, это шесть строк),
и задача сводится к аккуратному переносу:

```js
toNumber(undefined)  // NaN
toNumber(null)       // 0
toNumber(true)       // 1
toNumber(false)      // 0
toNumber('  42  ')   // 42 — пробелы по краям отбрасываются
toNumber('')         // 0 — пустая строка это ноль
toNumber('   ')      // 0 — строка из пробелов тоже
toNumber('0x1F')     // 31 — шестнадцатеричная запись
toNumber('привет')   // NaN
```

Это заодно закрывает половину вопросов теста «Преобразование типов» —
ученик не запоминает правила, а реализует их.

#### `method-properties` — algorithm

**Идея:** расширение существующей `is-idempotent`. По названию метода
вернуть объект из трёх флагов согласно RFC 9110:

```js
methodProperties('GET')     // { safe: true,  idempotent: true,  cacheable: true }
methodProperties('POST')    // { safe: false, idempotent: false, cacheable: true }
methodProperties('PUT')     // { safe: false, idempotent: true,  cacheable: false }
methodProperties('DELETE')  // { safe: false, idempotent: true,  cacheable: false }
methodProperties('HEAD')    // { safe: true,  idempotent: true,  cacheable: true }
methodProperties('WHATEVER')// null
```

Точка обучения — `POST`. Почти все уверены, что он не кэшируется, а в
RFC 9110 написано, что ответ на `POST` кэшируем — просто только при явных
заголовках свежести, в отличие от `GET`, который кэшируется по умолчанию.
Эту деталь невозможно вспомнить, её можно только прочитать; в условии
задачи стоит дать прямую ссылку на нужный раздел и попросить свериться.

#### `next-version` — algorithm

**Идея:** `nextVersion(current, changes)`, где `changes` — массив строк
`'fix' | 'feature' | 'breaking'`. По правилам семантического
версионирования вернуть следующую версию.

```js
nextVersion('1.4.2', ['fix', 'fix'])              // '1.4.3'
nextVersion('1.4.2', ['fix', 'feature'])          // '1.5.0'
nextVersion('1.4.2', ['feature', 'breaking'])     // '2.0.0'
nextVersion('1.4.2', [])                          // '1.4.2'
nextVersion('0.3.1', ['breaking'])                // '1.0.0'
```

Тонкости, за которыми придётся сходить в spec семвера: младшие числа
обнуляются при повышении старшего; побеждает самое сильное изменение в
списке, а не последнее.

#### `read-the-types` — algorithm

**Идея:** в заготовке дана сигнатура в стиле `.d.ts` (комментарием) и
пустая функция. Реализовать по сигнатуре, не имея словесного описания.

```js
/**
 * groupBy<T>(items: T[], key: (item: T) => string): Record<string, T[]>
 */
```

Плюс два вопроса, зашитые в служебную функцию: что вернётся для пустого
массива и сохраняется ли порядок внутри группы. Ученик должен вывести
ответы из типа — `Record<string, T[]>` уже говорит, что это объект с
массивами.

#### `shrink-the-case` — algorithm

**Идея:** дана функция `parseRange(text)` с багом, и служебная функция,
которая гоняет её на списке входов. Задача ученика — **не чинить**, а
найти минимальный вход, на котором она ломается, и вернуть его.

```js
function findFailingInput() {
  // верните самую короткую строку, на которой parseRange даёт неверный результат
}
```

Проверки: возвращённая строка действительно ломает функцию, и она не длиннее
некоторого предела. Задача необычная для платформы, но именно она учит
приёму из урока — и решается перебором, то есть кодом, а не угадыванием.

#### `good-question` — quiz, 4 вопроса

Даны четыре формулировки одного вопроса — выбрать пригодную для поиска и
для issue. Пояснения объясняют, что именно мешает в остальных: свои имена
переменных в тексте ошибки, отсутствие версии, «не работает» вместо
конкретного текста.

#### `document-the-function` — algorithm

**Идея:** дана функция, ученик отвечает на вопросы о её контракте, заполняя
объект:

```js
const contract = {
  emptyInput: /* что вернёт для [] */,
  throwsOnNull: /* true или false */,
  mutatesInput: /* true или false */,
  returnsNewArray: /* true или false */,
};
```

Проверки сверяют ответы с реальным поведением функции. Подглядеть можно —
и нужно: правильный способ ответить на эти вопросы — запустить функцию и
посмотреть, а не гадать по коду. Именно этому урок и учит.

### Проектная работа блока: «Разобраться в незнакомом API»

Это ключевая задача блока и единственная, где не помогает вообще ничего,
кроме документации. Формат — обычная `algorithm`-задача, потому что все
нужные API встроены в браузер и доступны в воркере.

**Задача `format-by-docs`.** Реализовать три функции, каждая из которых
решается одной строкой — если знать, какую опцию передать. Наизусть эти
опции не помнит никто.

```js
// 1. Цена в рублях: 1234.5 → '1 234,50 ₽'
formatPrice(1234.5)

// 2. Правильное окончание: 1 → '1 задача', 2 → '2 задачи', 5 → '5 задач'
formatTasks(5)

// 3. Сортировка «как в проводнике»: файл2 раньше файл10
sortFiles(['файл10.txt', 'файл2.txt', 'Файл1.txt'])
```

Решения:

1. `Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB' })`
2. `Intl.PluralRules('ru-RU')` — вернёт `'one'`, `'few'`, `'many'`,
   остаётся сопоставить со словами.
3. `localeCompare` с опциями `{ numeric: true, sensitivity: 'base' }`.

Почему это хорошая проектная работа:

- **Нельзя решить по памяти.** Ни один человек не помнит, что во втором
  случае нужны именно `PluralRules` и что категорий в русском не две:
  `one`, `few`, `many` для целых плюс `other` для дробных.
- **Нельзя решить перебором.** Опции не угадываются.
- **Результат проверяемый.** Обычные проверки на строку — раннер уже умеет.
- **Полезно в работе прямо завтра.** Три самые частые задачи вёрстки
  интерфейсов на русском языке, и все три обычно решают костылями.
- **Показывает, что стандартная библиотека больше, чем кажется.**
  Отдельный маленький инсайт: половина того, ради чего подключают
  библиотеки, уже встроена в браузер.

Единственная тонкость реализации: `Intl.NumberFormat` разделяет разряды не
обычным пробелом, а неразрывным (в части браузеров — узким неразрывным).
Проверка должна это учитывать: либо сравнивать после нормализации пробелов,
либо задать разделитель явно и написать об этом в условии. Само по себе это
отличная иллюстрация того, зачем открывать документацию: строка выглядит
правильной, а `===` даёт `false`.

# Cube — платформа для обучения программированию

Модуль = теория (видео + статьи) → задачи. Код пишется в редакторе и выполняется
прямо в браузере: сначала «Запустить» для черновой проверки, потом «Отправить на
проверку» — прогон тестов и зачёт задачи.

## Запуск

```bash
npm install
npm run dev        # http://127.0.0.1:3000
npm run build      # прод-сборка
```

Next.js 16 (App Router, Turbopack) + TypeScript + Tailwind v4, редактор — CodeMirror 6.

## Как устроен запуск кода

Шов между UI и исполнителем — [`src/lib/runner`](src/lib/runner). Страница задачи знает
только `Task`, `Runner` и `RunResult`, поэтому новый исполнитель (iframe для DOM-задач,
серверный раннер для Go) подключается без правок интерфейса — выбор идёт по `task.kind`
в [`index.ts`](src/lib/runner/index.ts).

**Два режима.** `run` — выполнить код и показать вывод, ничего не проверяя. `submit` —
прогнать тесты и вынести вердикт; при всех зелёных задача отмечается решённой.

**JS-задачи** (`kind: 'algorithm'`) исполняются в Web Worker из Blob, с таймаутом 4 с —
бесконечный цикл гасится `worker.terminate()`, интерфейс не виснет.

Скрипт воркера собирается строго в таком порядке:

```
строка 1      пролог: подмена console.*
строки 2..N+1 код пользователя — как есть, без обёрток
дальше        харнесс: сравнение, прогон тестов, отправка результата
```

Код пользователя не оборачивается в `new Function`: тогда номера строк в `error.stack`
совпадают с номерами в редакторе с точностью до известного смещения (`LINE_OFFSET = 1`,
пролог занимает ровно одну строку). Функции харнесса объявлены через `function`, поэтому
поднимаются в начало скрипта и доступны прологу.

Сравнение результатов — глубокое (массивы, объекты, вложенность, `Map`/`Set`, `NaN`).
Каждый тест обёрнут в свой `try/catch`: упавший помечается проваленным, остальные
продолжают выполняться. Логи пользователя и результаты тестов — разные поля `RunResult`.

## Как добавить контент

**Задачу** — файл в [`src/lib/tasks`](src/lib/tasks) и строка в `index.ts` того же каталога:

```ts
export const myTask: AlgorithmTask = {
  kind: 'algorithm',
  slug: 'my-task',
  title: 'Название',
  language: 'javascript',
  description: 'Текст в мини-markdown: абзацы, списки, `код`, ```блоки```, **жирный**',
  starterCode: 'function solution(x) {\n\n}\n',
  tests: [{ name: 'solution(1) === 2', input: [1], expected: 2 }],
};
```

По умолчанию от ученика ждут функцию `solution`; её вызывают ровно один раз на тест.

**Задачи с несколькими функциями и задачи «породи ошибку».** У теста есть
необязательные поля `fn` и `throws`:

```ts
tests: [
  { name: 'reference() порождает ReferenceError', fn: 'reference', input: [], throws: 'ReferenceError' },
  { name: 'type() порождает TypeError',           fn: 'type',      input: [], throws: 'TypeError' },
]
```

`fn` — имя функции, если оно не `solution`. `throws` переворачивает проверку:
успех — это выброшенная ошибка нужного типа, а вернувшийся результат считается
провалом. Тип сверяется через `instanceof`, а не по тексту сообщения: формулировки
у браузеров разные. Если текст всё же важен, есть `messageIncludes` — но с ним
задача может не пройти в Safari.

Функция ищется прямым `eval` по имени: объявления через `const` на верхнем уровне
в `globalThis` не попадают, а лексическое окружение их видит.

**Модуль с уроками** — через админку `/admin/modules`, править код не нужно.
Файлы в [`src/lib/content/seed`](src/lib/content/seed) — только стартовое
наполнение для `npm run db:seed`. Урок собирается из блоков:

```ts
blocks: [
  { type: 'text', markdown: 'Теория в мини-markdown' },
  { type: 'video', url: 'https://youtu.be/ID', title: 'Разбор темы' },
  { type: 'article', url: 'https://learn.javascript.ru/variables', title: 'Переменные',
    source: 'learn.javascript.ru', note: 'Зачем читать' },
  { type: 'task', slug: 'errors', note: 'Закрепим на практике' },
]
```

**Видео проигрывается прямо на странице.** Распознаются ссылки YouTube (`watch?v=`,
`youtu.be`, `/embed/`, `/shorts/`), Vimeo, RuTube, VK, а также прямые файлы
`.mp4/.webm/.ogg/.mov` — они играют в теге `<video>`. Пустой `url` показывает
заметную заглушку «вставьте ссылку», ничего не ломая. Логика — в
[`VideoEmbed.tsx`](src/components/VideoEmbed.tsx).

Порядок прохождения модуля — сначала все уроки, потом задачи из `taskSlugs`. Кнопка
внизу урока отмечает его прочитанным и ведёт на следующий шаг.

**Связка теории и практики.** Блок `task` рисует в уроке кнопку «Решать задачу»,
так что из лекции можно уйти к практике, не возвращаясь к списку. На странице
задачи внизу описания всегда висит ссылка на следующий шаг — «Следующий урок»
или «Следующая задача», в зависимости от того, что дальше по модулю. Раньше такая
ссылка появлялась только после успешной сдачи.

## Сообщения о багах

Кнопка с жучком есть на странице урока и в панели задачи. Она открывает модалку
с названием текущего урока или задачи и полем для описания; плейсхолдер подсказывает
структуру — что пошло не так и код. Отправить может и гость из демо, тогда автор
не указывается.

Сообщения складываются в таблицу `bug_reports` и видны админу в `/admin/bugs`:
новые сверху, каждое можно пометить разобранным или удалить.

## Темы

Пять тем полными наборами CSS-переменных в [`globals.css`](src/app/globals.css),
переключение — `data-theme` на `:root`, выбор хранится в localStorage. Тёмные: графит
(по умолчанию), уголь, контраст. Светлые: туман, пергамент. `prefers-color-scheme`
намеренно не используется — выбор пользователя единственный источник истины. Тема
применяется инлайновым скриптом в `<head>` до первой отрисовки, поэтому нет мигания.

Подсветка кода тоже построена на этих переменных, так что редактор перекрашивается
вместе с интерфейсом.

## Вход и учётные записи

Регистрации на сайте нет: учётки заводит владелец и передаёт логин с паролем
ученику. Вход — Auth.js (NextAuth v5) с Credentials-провайдером, сессии в JWT,
пароли хранятся как scrypt-хеш (`scrypt:<соль>:<хеш>`, без внешних библиотек).

Обычно учётки заводят в админке. Из консоли — когда админа ещё нет:

```bash
npm run user:add -- --email ivan@example.com --password "секрет" --name Иван
npm run user:add -- --email ivan@example.com --password "новый" --reset   # смена пароля
npm run user:role -- --email ivan@example.com --role admin               # первый администратор
npm run user:delete -- --email ivan@example.com                          # вместе с прогрессом
npm run user:list
```

Все страницы кроме `/login` требуют входа — за это отвечает `requireUser()`
из [`src/lib/session.ts`](src/lib/session.ts). API-роуты проверяют сессию
самостоятельно и отвечают 401 без неё.

**Роль лежит в JWT**, поэтому после её смены пользователь должен выйти и войти
заново — иначе сессия останется со старыми правами.

## Админка

Раздел `/admin` доступен роли `admin`, ссылка появляется в шапке. Проверка
роли — `requireAdmin()` на каждой странице и в каждом серверном действии:
прятать кнопки в интерфейсе недостаточно.

Что можно делать: заводить и удалять учеников, менять им пароли и роли;
создавать модули, писать уроки (блоки текста, видео и ссылок на статьи),
менять порядок; собирать в модуль задачи из готового списка.

Задачи остаются файлами: у них проверки — это код, и веб-форма для него плохой
инструмент. В админке задача только привязывается к модулю.

## Демо-доступ

Часть материалов можно открыть без входа. У каждого урока и у каждой задачи
внутри модуля есть переключатель «в демо» — там же, в редакторе модуля.
Отмеченное собирается на странице `/demo`, ссылка на неё появляется на форме
входа (и только если в демо что-то отмечено).

В демо код запускается и проверки прогоняются по-настоящему, но прогресс
не сохраняется: аккаунта нет. Ссылки «дальше» ведут только на другие демо-шаги,
чтобы гость не упирался в форму входа. Всё остальное закрыто: страница урока
и страница задачи сами проверяют признак демо и отправляют на `/login`.

## База данных и прогресс

Postgres через Drizzle. Таблицы: `users`, `submissions` (история отправок
на проверку), `lesson_progress` (прочитанные уроки), `modules`, `lessons`
и `module_tasks` (учебные материалы). «Решено» — это наличие записи
в `submissions` с `passed = true`, отдельной таблицы прогресса нет.
Блоки урока лежат в `lessons.blocks` одним JSONB: урок правится целиком
одной формой.

```bash
npm run db:generate   # SQL-миграции из схемы
npm run db:migrate    # накатить их
npm run db:seed       # первичное наполнение из src/lib/content/seed
```

Переменные окружения — см. [.env.example](.env.example). С `DATABASE_URL`
приложение работает с Neon, без него поднимает встраиваемый Postgres (PGlite)
в папке `.pglite`: разработка и проверка не требуют облачной БД.

Прогресс читают серверные страницы через
[`src/lib/progress.ts`](src/lib/progress.ts) и передают компонентам пропсами;
клиент только сообщает о событиях через
[`progressClient.ts`](src/lib/progressClient.ts) и вызывает `router.refresh()`.

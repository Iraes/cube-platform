# Cube — памятка агенту

Платформа для обучения программированию. Владелец пишет уроки и задачи, выдаёт
ученикам логины, ученики решают задачи с запуском кода прямо в браузере.

Общайся с владельцем **по-русски**. Интерфейс, тексты задач и комментарии
в коде — тоже на русском.

## Где что читать

| Файл | О чём |
|---|---|
| [README.md](README.md) | Как всё устроено: раннер, контент, темы, БД, админка, тесты |
| [PLAN.md](PLAN.md) | Цели, решения владельца с цитатами, статус этапов |
| `node_modules/next/dist/docs/` | Актуальные доки Next.js — сверяйся перед правками |

Владелец формулирует задачи в свободной форме и уточняет их по ходу. Его решения
записаны в PLAN.md разделом «Решения владельца» — **они имеют приоритет над
первоначальным ТЗ**. Появилось новое решение — допиши туда, иначе потеряется.

## Команды

```bash
npm run dev          # dev-сервер, http://localhost:3000
npm run typecheck    # tsc --noEmit, гоняй после каждой правки
npm run build        # прод-сборка
npm run db:generate  # SQL-миграция из схемы
npm run db:migrate   # накатить миграции
npm run db:seed      # первичное наполнение из src/lib/content/seed
npm run user:add -- --email a@b.c --password "секрет" --name Имя --role admin
npm run user:role -- --email a@b.c --role admin
npm run user:delete -- --email a@b.c
npm run user:list
```

## Грабли окружения — прочитай до первой команды

**Windows + PowerShell ломает кириллицу.** `Get-Content ... | Set-Content` читает
файл в неверной кодировке и превращает русский текст в мусор. Один раз так был
испорчен `src/lib/actions/admin.ts`, спасал `git checkout`. Правь файлы только
инструментами Edit/Write, а PowerShell оставь для команд.

**Многострочные git-сообщения через here-string тоже ломаются** — аргумент
разваливается по пробелам. Пиши сообщение во временный файл и делай
`git commit -F путь/к/файлу`.

**Соединение с базой нестабильно.** Neon живёт во Франкфурте, и с машины
владельца соединение периодически не устанавливается: `ConnectTimeoutError`,
10 секунд ожидания. Разогретый запрос — около 70 мс, первый после паузы —
500–700 мс. Если что-то «тормозит» или падает с `fetch failed` — сначала
проверь, не сеть ли это, а уже потом ищи в коде. Для локальной разработки
можно убрать `DATABASE_URL` из `.env.local`: приложение поднимет встроенный
PGlite в папке `.pglite`, и всё станет мгновенным.

**База у прода и у разработки одна.** Отдельной боевой не заводили, поэтому
`db:migrate`, `db:seed` и любой скрипт, запущенный локально с `DATABASE_URL`,
меняет данные живого сайта. Ученики увидят правку сразу, без деплоя.
Из этого же следует порядок: миграцию накатывай **до** пуша, иначе на Vercel
поедет код, которому не хватает колонки.

**Автодеплой на Vercel умеет тихо отваливаться.** Вебхук GitHub → Vercel
пропадает без единой ошибки: пуши уходят, а деплои просто перестают
появляться в списке. Права тут обычно ни при чём — если приложению Vercel
выдан доступ, а репозиторий приватный, GitHub на запрос без прав отвечает
404 «не найдено», и Vercel показывает «repository can't be found», что уводит
в ложную сторону. Диагностика: GitHub → репозиторий → Settings → Webhooks →
хук на `vercel.com` → Recent Deliveries. Нет доставок после какой-то даты —
хук мёртв. Лечение: Vercel → проект → Settings → Git → Disconnect и Connect
заново, это пересоздаёт хук; переменные окружения при этом сохраняются.
Один раз так простояли три пуша.

**Секреты не проси и не печатай.** `DATABASE_URL` и `AUTH_SECRET` лежат
в `.env.local`, он в `.gitignore`. Перед пушем проверяй `git ls-files`.

**Время нельзя брать из окружения.** На машине владельца процесс живёт
в Москве, на Vercel — в UTC, и одно и то же событие покажется на три часа
раньше. Форматируй через `src/lib/datetime.ts`: там пояс задан явно
(`PLATFORM_TIMEZONE`, по умолчанию `Europe/Moscow`). `getDate()`,
`getHours()` и `toLocaleString()` без пояса — та же ловушка.

## Инварианты, которые легко сломать

**Не передавай серверные объекты целиком в клиентские компоненты.** Всё, что
попадает в пропсы, попадает в разметку страницы и видно через инструменты
разработчика. На этом уже обжигались: урок передавался целиком, и вместе с ним
уезжали правильные ответы встроенных тестов. Теперь страница урока передаёт
отдельно заголовок, описание и очищенные блоки (`toPublicBlocks`), а ответы
сверяет сервер. Добавляешь что-то с «правильным ответом» — чисти на сервере.

**Порядок сборки скрипта воркера трогать нельзя.** Строка 1 — пролог с подменой
`console.*`, дальше код ученика как есть, дальше харнесс. Отсюда `LINE_OFFSET = 1`
и правильные номера строк в ошибках. Обернёшь код ученика во что-нибудь — номера
строк поедут, а это главное удобство платформы. Функции харнесса объявлены через
`function` намеренно: они поднимаются и доступны прологу.

**Тип ошибки в задачах «породи ошибку» сверяется через `instanceof`, а не по
тексту.** Формулировки различаются: Chrome пишет «a is not defined», Safari —
«Can't find variable: a». Поле `messageIncludes` есть, но им лучше не пользоваться.

**Роль хранится в JWT.** После смены роли пользователь должен выйти и войти
заново, иначе останется со старыми правами. Это не баг, это следствие
JWT-сессий; просто помни и предупреждай владельца.

**Проверка прав — на сервере.** `requireAdmin()` вызывается на каждой странице
раздела `/admin` и в каждом серверном действии, `requireTeacher()` — на каждой
странице `/students`. Прятать кнопки в интерфейсе недостаточно. Layout не
считается защитой: при частичной навигации Next может отрисовать вложенную
страницу, не выполнив layout заново, поэтому проверка дублируется в обоих.

**Ошибки Postgres приходят завёрнутыми.** Drizzle оборачивает ошибку драйвера
в свою, поэтому код (`23503` и подобные) лежит в `cause`, а не сверху — см.
`src/lib/db/errors.ts`.

## Что где лежит

- `src/lib/runner/` — шов между интерфейсом и исполнителем кода. Страница знает
  только `Task`, `Runner`, `RunResult`; выбор идёт по `task.kind` в `index.ts`.
  Здесь появится Go через серверный раннер.
  DOM-задачи живут в `domSandbox.ts` (сборка страницы-песочницы)
  и `iframeDomRunner.ts` (прогон проверок в скрытом фрейме).
- `src/lib/tasks/` — задачи **файлами** в репозитории, по файлу на задачу.
  Регистрируются в `index.ts` того же каталога.
- `src/lib/content/` — модули и уроки, живут **в БД** и правятся в админке.
  Файлы в `seed/` — только стартовое наполнение.
- `src/lib/db/` — схема, клиент, запись контента.
- `src/lib/quiz.ts` — проверка тестов, общая для теста-в-уроке и задачи-теста.
- `src/lib/progress.ts` — прогресс: и запись, и отчёты для преподавателя.
  Считать проценты нужно по программе, витринные модули в неё не входят.
  «Последний заход» живёт отдельно, в `users.lastSeenAt`: прогресс двигают
  только отправка решения и «Прочитано», а тихий заход — тоже событие.
- `src/app/admin/` — раздел управления, закрыт ролью `admin`.
- `src/app/students/` — прогресс учеников, открыт ролям `teacher` и `admin`.

Почему задачи в файлах, а контент в БД: у задачи проверки — это исполняемый код,
и веб-форма для него плохой инструмент, а ошибка в проверках рушит прогресс тех,
кто задачу уже сдал. Уроки же меняются часто и должны редактироваться без деплоя.

## Как проверять сделанное

Одного `typecheck` мало — гоняй сценарий в браузере. У владельца обычно уже
поднят dev-сервер на порту 3000; подключайся к нему, а не поднимай второй.

Порядок, который себя оправдал:

1. `npm run typecheck`;
2. открыть страницу и прогнать сценарий целиком, включая ошибочные пути —
   неверное решение, пустой ввод, отсутствующую функцию;
3. посмотреть, что реально ушло в браузер (`fetch(location.href)` и поиск
   по HTML), если добавлял что-то, чего ученик видеть не должен;
4. `npm run build` перед коммитом.

Тексты ошибок для ученика пиши человеческими: не «ожидалось 5, получено -1»
в вакууме, а так, чтобы было понятно, что делать дальше.

## Состояние

Готово: задачи с кодом, уроки с видео и статьями, прогресс в БД, вход по
выданным логинам, админка, демо-доступ, тесты с выбором ответа, сообщения
о багах, DOM-задачи с живым превью, витринные модули «только в демо»,
раздел преподавателя с прогрессом учеников (`/students`).

Развёрнуто на Vercel: проект подключён к `git@github.com:Iraes/cube-platform.git`,
пуш в `main` собирает продакшен. В переменных окружения проекта заданы
`DATABASE_URL` и `AUTH_SECRET`, при необходимости `PLATFORM_TIMEZONE`
(по умолчанию `Europe/Moscow`).

База у прода и у разработки одна — та же Neon. Значит, правки контента через
админку и скрипты видны на боевом сайте сразу, без деплоя, а миграции нужно
накатывать **до** пуша: код на Vercel поедет по уже обновлённой схеме.

Дальше по плану — задачи «напиши тесты» и трекер задач (этапы 1c и 4 в PLAN.md).
